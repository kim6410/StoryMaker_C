## 0. 이 문서의 성격

이 문서는 현재 Claude Code가 진행 중인 단계 11 작업을 중단시키거나 방향을 급하게 바꾸기 위한 문서가 아니다.

현재 진행 중인 다음 작업을 그대로 유지한다.

- 기존 AI 코드 조사
- `app/ai/prompt_builder.py`, `gemini_client.py` 구조 조사
- 업체관리 라우트와 템플릿 구현
- Provider·Prompt DB 스키마 마이그레이션
- `/admin/providers` 구현
- `/admin/prompts`, `/admin/prompts/{id}` 구현
- `scripts/db_selftest.py` 보정
- 8032 검증 서버 준비
- 기존 단계 6~10 기능 회귀 방지

이 문서는 위 작업이 자연스러운 단위로 완료된 뒤, 같은 단계 11 안에서 추가로 반영해야 할 UI·UX·운영성 보완 요구를 정리한 것이다.

우선 현재 하던 작업을 기능 단위로 완결하고 테스트한 뒤 이 문서를 읽고 이어서 진행한다.

## 3. 현재 화면에서 직접 확인된 UI·UX 문제

현재 사용자 화면과 관리자 화면은 기능 검증에는 사용할 수 있지만 서비스 화면으로는 거칠다.

### 3-1. 공통 문제

- 화면이 지나치게 넓고 빈 공간이 많다.
- 카드가 좌우로 과도하게 퍼져 정보 밀도가 낮다.
- 배경과 카드 색상이 비슷해 시각적 위계가 약하다.
- 모든 메뉴 아이콘이 동일한 점 모양이다.
- 사용자 메뉴와 관리자 메뉴의 성격이 명확히 분리되지 않는다.
- 버튼 높이와 크기, 카드 여백이 화면마다 다르다.
- 기술 검증판처럼 보이는 용어가 남아 있다.
- 개발용 브랜드인 `StoryMaker Claude Lab`이 그대로 노출된다.
- 종 모양 알림이 실제 알림이 아니라 샘플 문구를 표시한다.
- 인라인 `style`이 많아 공통 수정과 반응형 유지가 어렵다.
- 실제 데이터가 없는 영역이 큰 빈 박스나 검은 영상 영역으로 보인다.
- PC 화면에서 정보가 너무 멀리 떨어져 있어 작업 동선이 길다.

### 3-2. 사용자 대시보드 문제

- 큰 숫자 카드가 화면 대부분을 차지한다.
- 현재 업체와 대표 이미지가 핵심 영역에 보이지 않는다.
- 새 콘텐츠 만들기가 강조되지만 업체 정보와 연결감이 약하다.
- 최근 완성 영상이 검은 박스로 보일 수 있다.
- 제목, 업체명, 제작일, 대표 썸네일, 재생 버튼의 위계가 부족하다.
- 보관함과 최근 작업이 실제 콘텐츠 서비스처럼 보이지 않는다.

### 3-3. 관리자 화면 문제

- 통계 카드가 3줄 이상 반복돼 우선순위가 보이지 않는다.
- 오늘 처리할 실패 작업보다 전체 누적 숫자가 먼저 보인다.
- 관리자 센터와 사용자 화면이 같은 메뉴 안에 길게 이어진다.
- 관리자 메뉴에 업체관리, Provider, Prompt, 구독·사용량 운영 흐름이 충분히 드러나지 않는다.
- 최근 실패 작업에서 재시도, 오류 상세, 파일 검사로 바로 이어지지 않는다.
- 숫자 카드가 많지만 운영자가 무엇을 먼저 처리해야 하는지 알기 어렵다.

## 4. UI·UX 보완 우선순위

현재 기능 구현을 방해하지 않도록 아래 순서를 지킨다.

### 우선순위 A. 업체 등록과 실제 데이터 입력 흐름

기능과 화면이 모두 완성돼야 한다.

- 업체 목록
- 신규 업체 등록
- 업체 수정
- 기본 업체 설정
- 업체 활성·비활성
- 대표 이미지
- 콘텐츠 사진 복수 업로드
- 콘텐츠 영상 복수 업로드
- 업로드 미리보기
- 업로드 취소
- 파일 검증
- 저장 성공·실패 상태
- 다른 사용자 접근 차단
- 관리자 열람

UI 기준:

- 입력 필드를 한 화면에 과도하게 늘어놓지 않는다.
- 기본정보, 지역·연락처, 마케팅 정보, 콘텐츠 요청사항, 이미지·영상으로 섹션을 나눈다.
- 필수 필드와 선택 필드를 구분한다.
- 긴 설명 입력은 textarea 높이와 도움말을 제공한다.
- 저장 버튼은 화면 하단과 상단 중 한 곳에 일관되게 배치한다.
- 모바일에서 저장 버튼이 화면 밖으로 사라지지 않게 한다.
- 신규 등록 완료 후 업체 목록 또는 상세 화면에서 결과를 바로 확인할 수 있게 한다.

### 우선순위 B. 마이페이지 실제 사용성

마이페이지는 단순 정보 표시가 아니라 사용자 계정과 업체를 관리하는 허브가 돼야 한다.

구성 권장:

1. 내 계정
2. 비밀번호 변경
3. 기본 업체
4. 업체 관리 바로가기
5. 구독정보
6. 이번 달 사용량
7. 보관함 사용량
8. 최근 로그인과 계정 상태

UI 기준:

- 저장 가능한 항목과 읽기 전용 항목을 시각적으로 구분한다.
- 비밀번호 변경은 별도 카드나 모달로 분리한다.
- 현재 기본 업체와 대표 이미지를 보여준다.
- 업체가 없으면 `업체 등록하기` CTA를 강하게 표시한다.
- 사용량과 구독정보를 숫자만 나열하지 말고 진행 막대와 종료일을 함께 보여준다.

### 우선순위 C. 사용자 대시보드 재정비

실제 업체와 작업 데이터가 들어간 뒤 수정한다.

상단 권장 구성:

- 현재 업체 대표 이미지
- 업체명
- 기본 업체 변경
- 이번 달 사용량
- 잔여 제작 횟수
- 구독상태
- 새 콘텐츠 만들기 CTA

중앙 권장 구성:

- 진행 중 작업
- 실패 작업
- 최근 완성 콘텐츠

최근 완성 콘텐츠 카드:

- 대표 썸네일
- 제목
- 업체명
- 제작일
- MP4 재생
- 결과 보기
- 보관함 이동
- 다운로드

금지:

- 검은 빈 영상 박스만 표시
- 대형 숫자 카드만 반복
- 지나치게 넓은 빈 카드
- 클릭 가능한 영역과 단순 정보 카드의 구분 없음

### 우선순위 D. 관리자 센터 UI·UX

관리자 계정에는 `사용자 화면`과 `관리자 센터` 전환 구조를 제공한다.

관리자 센터 기본 메뉴 권장:

- 운영 대시보드
- 회원관리
- 업체관리
- 작업관리
- 사용량·구독
- Provider 관리
- Prompt 관리
- TTS·렌더 진단
- 저장공간
- 감사로그

관리자 대시보드 첫 화면 우선순위:

1. 지금 처리해야 할 실패 작업
2. Provider·TTS·렌더 장애 상태
3. 신규 가입과 유료 전환
4. 저장공간 경고
5. 오늘·이번 달 작업량
6. 누적 통계

통계 카드 수는 첫 화면에서 과도하게 늘리지 않는다.

상세 통계는 접기 또는 별도 리포트 영역으로 내린다.

최근 실패 작업에는 다음을 바로 제공한다.

- 실패 단계
- 오류 요약
- 재시도 가능 여부
- 재시도
- 파일 검사
- 사용자·업체
- 작업 상세
- 관리자 메모

### 우선순위 E. 보관함 UI·UX

보관함은 결과물 중심으로 재구성한다.

- 제작일
- 상태
- 채널 수

- `새 콘텐츠 만들기` CTA
- 업체가 없으면 업체 등록 CTA 우선

공통 CSS 토큰과 컴포넌트로 정리한다.

필수:

## 5. 브랜드와 개발 흔적 정리

### 5-1. 브랜드

현재 노출되는 `StoryMaker Claude Lab`은 개발용 명칭으로 본다.

사용자 화면에서는 `StoryMaker`로 통일한다.

관리자 화면에서도 `StoryMaker 관리자 센터` 정도로 명확히 표시한다.

단, 앱 설정과 내부 로그명을 무리하게 한 번에 변경하지 않는다.

우선 화면 텍스트와 브라우저 제목부터 정리한다.

### 5-2. 샘플 알림

`새 알림이 없습니다. (샘플)` 같은 mock 문구는 완료 화면에 남기지 않는다.

가능한 안전한 선택:

- 실제 최근 실패 작업·저장공간 경고·회원 상태 변경과 연결
- 아직 실제 알림 시스템을 만들지 않는다면 종 아이콘 제거

샘플 동작을 실제 기능처럼 남겨두지 않는다.

### 5-3. 메뉴 아이콘

모든 메뉴가 동일한 `•` 아이콘을 쓰지 않게 한다.

StoryMaker_C 내부에서 직접 작성한 SVG 또는 CSS 기반 아이콘을 사용한다.

외부 V1·Beta 아이콘 파일을 복사하지 않는다.

## 6. 성능과 느린 화면 보완

현재 앱은 기능이 돌아가지만 화면과 제작 과정이 느리게 느껴진다.

무작정 최적화하지 말고 단계별로 계측한다.

필수 측정:

- 로그인 응답시간
- 대시보드 응답시간
- 업체 목록 응답시간
- 업체 저장 응답시간
- 보관함 목록 응답시간
- 관리자 대시보드 응답시간
- AI 생성시간
- TTS 생성시간
- MP4 로컬 렌더시간
- MP4 서버 렌더시간

8032는 사용자가 직접 돌아보는 검증 서버로 유지한다.

- 사용자에게 전달할 주소는 8032로 통일
- 검증 서버임을 화면 또는 문서에 명시
