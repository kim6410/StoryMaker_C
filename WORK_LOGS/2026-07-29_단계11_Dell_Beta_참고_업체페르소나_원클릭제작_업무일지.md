# 2026-07-29 단계11 보완 - Dell Beta(mystorymaker.net) 참고, 업체 페르소나·원클릭 제작

## 요청 배경

사용자가 `https://app.mystorymaker.net/v1/?page=betaProduction` (Dell 서버의 별도 운영 Beta
버전, `\\192.168.0.32\StoryMaker_1\StoryMaker_beta`와 동일 계열) 화면을 브라우저로 직접
살펴본 뒤, 구성과 작업흐름을 StoryMaker_C에 적용해달라고 요청함. 실제 브라우저(Claude in
Chrome)로 화면을 조회했고(조회만, 스크립트/AI원고 생성 버튼은 실제 과금·쿼터가 소모될
수 있어 누르지 않음), 파악한 구조를 사용자에게 보고 후 두 가지 우선순위를 확인받음.

- 적용 범위: **콘텐츠 제작 흐름을 단일페이지 "딸깍 제작" 방식으로 재구성**
- 페르소나 연동 범위: **업체 페르소나를 이번에 바로 AI원고 생성 프롬프트까지 연동**

## Beta 화면에서 확인한 구조 (읽기 전용 조사, 수정 없음)

- 딸깍 제작: 업체정보 고정표시 → ①기초 콘텐츠 입력(자유 텍스트) → ②이미지/동영상 선택
  → ③스크립트 생성(로컬, "TORI" 마스코트, Pure Local Pipeline) → ④AI원고 생성.
  "원고 생성 방식: 브라우저 직접/API" 토글 있음.
- 업체 정보: 기본 작성 채널/글자수, **감성 톤 11개 태그 다중선택**(따뜻함/전문가/친근함/
  신뢰감/현장감/진정성/차분함/활기/담백함/순박함/진지함), 핵심 키워드(태그칩), **페르소나
  상세 설명**(업체 역사·전문분야·말투 철학·콘텐츠 방향을 담은 긴 서술형 텍스트, AI 프롬프트
  브랜드보이스로 쓰이는 것으로 추정).

## 범위 결정과 이유 (자동 선택, 이유 기록)

Beta의 ③"스크립트 생성"(로컬 WebGPU/TORI 마스코트 브랜딩 파이프라인)은 완전히 별도의
대규모 신규 기능(클라이언트측 로컬 모델, 브랜드 캐릭터 자산, 로컬/API 이원화 생성 엔진)이라
이번 작업 범위에서 제외했다. 대신 "딸깍(원클릭)"의 핵심인 **클릭 수 최소화**에 집중해,
기존 PRG 서버 렌더링 아키텍처를 유지한 채(기존 정상 기능 보존, 최소 수정, 복구 가능성
우선) 흐름만 압축했다. 이유: 새 로컬 AI 파이프라인은 검증되지 않은 대규모 변경이라
단계11의 "실제 동작 확인 전 성공 선언 금지" 원칙과 충돌 위험이 크다.

## 구현

### 1) 업체 감성 톤 다중선택 (스키마 변경 없음)
- `app/templates/company_form.html`: 기존 `tone_preference` 단일 텍스트 입력을 Beta와
  동일한 11개 태그 체크박스 그리드로 교체. 기존 `tone_preference` 컬럼을 그대로 재사용해
  콤마로 join한 문자열로 저장(마이그레이션 불필요, 기존 데이터 그대로 호환).
- `app/main.py` `companies_create`/`companies_update`: `tone_preference: str` 파라미터를
  `tone_tags: list[str] = Form([])`로 교체하고 `",".join(...)`으로 변환해 기존
  `_company_form_fields()`에는 그대로 넘김(그 아래 계층 무변경).
- `업체 소개` 필드 placeholder를 "AI 원고 생성 시 브랜드 보이스로 그대로 반영됩니다"로
  보강해 Beta의 페르소나 서술 유도 방식을 참고.

### 2) 업체 페르소나 → 실제 AI 프롬프트 연동
- `app/ai/prompt_builder.py`: `PromptContext`에 `brand_persona`(=업체 소개),
  `must_include`, `free_request` 3개 필드 추가. `_business_context_block()`의 JSON
  데이터 블록에 포함. 시스템 규칙에 "brand_persona는 문체·분위기 참고용(사실 근거 아님)",
  "must_include는 결과물에 반드시 자연스럽게 포함", "free_request는 다른 원칙과 충돌하지
  않는 범위에서 반영" 3줄 추가.
- `app/ai/service.py` `_build_context()`: 제작 화면에는 이 3개 필드 입력란이 없으므로
  (업체에만 존재하는 값) company_id가 있으면 항상 최신 업체 정보에서 가져오도록 함
  (core_strength/forbidden_words의 기존 스냅샷-우선-업체-보완 패턴과 구분해서 처리).
- `generate_for_project`/`generate_channels_for_project`/`regenerate_channel_for_project`
  세 곳 모두 `_build_context()`를 공유하므로 한 곳 수정으로 전체 생성 경로에 반영됨.

### 3) 콘텐츠 제작 원클릭("딸깍 제작") 재구성
- `app/main.py` `create_content_job()`: 프로젝트 생성 직후, 기존에는 상태 페이지로
  리다이렉트해 사용자가 "생성하기"를 한 번 더 눌러야 했던 것을, 이번에 같은 요청 안에서
  바로 `generate_channels_for_project()`까지 이어서 호출하도록 변경. 성공하면 채널 결과
  페이지로 바로 이동, 실패하면 기존 상태 페이지의 오류 표시·재시도 버튼으로 자연스럽게
  이어짐(별도 롤백 로직 불필요, 기존 재시도 경로 그대로 재사용).
- `app/templates/content_new.html`: 페이지 제목을 "딸깍 제작"으로, 안내문과 단계
  표시(steps)를 "입력·사진선택·제작 시작(한 번에)"로, 제출 버튼을 "딸깍 제작 시작
  (SNS 8채널까지 자동 생성)"으로 변경.

## 검증 (포트 8033, 8032/8031 무관섭)

1. Gemini를 호출하지 않는 로컬 검증: 테스트 업체에 description/must_include/free_request
   저장 후 `_build_context()` + `build_channels_prompt()`를 직접 호출해 실제 프롬프트
   문자열에 세 값이 그대로 포함되는지 확인 (PASS, API 비용 없음).
2. httpx E2E(8033): 로그인 → 업체 감성 톤 3개 선택 저장 → 수정 화면에서 동일하게 체크된
   상태로 복원되는지 확인(PASS) → `/content/new` 페이지에 "딸깍 제작 시작"/"한 번에
   이어서 만들어집니다" 문구 노출 확인(PASS) → 사진 선택 후 1회 제출.
   - 1차 제출은 실제 Gemini 호출 중 예외로 실패(`gen_error=unknown_provider_error`)했으나,
     상태 페이지가 200으로 정상 표시되어 기존 재시도 경로가 살아있음을 확인(설계대로
     동작). 같은 프로젝트로 생성 함수를 다시 호출하니 정상 성공(ok=True)하고 채널 결과
     페이지가 200으로 렌더링됨 — AI 응답 검증 단계의 비결정적 실패(모델 출력 편차)로
     보이며, 이번에 수정한 라우팅/페르소나 연동 코드 자체의 결함은 아님(재현되지 않음,
     기존에도 동일 생성 함수를 쓰던 경로이므로 이번 변경으로 새로 생긴 위험은 아님).
3. `scripts/db_selftest.py` 24/24 PASS 재확인(회귀 없음).

이번 검증에서 실제 Gemini API를 2회 호출했다(사용자 실제 이용과 동일한 정상 과금 범위,
반복 재시도는 하지 않음). 테스트에 사용한 임시 스크립트는 검증 후 즉시 삭제, 8033 서버는
종료함. 8032(사용자 실사용 서버)는 이번 작업 중 전혀 건드리지 않음 — 반영하려면 사용자가
8032를 재시작해야 함(uvicorn 코드 자동 반영 안 됨).
