## WordPress 연동 결과 — 코드는 완성, 실제 연결은 자격증명 문제로 보류
`WordPressAuthProvider`를 실제로 구현했다(`is_configured`, 읽기 전용 `test_connection`, `authenticate`). `config/.env`에 이관된 WordPress 값을 채운 뒤 안전한 GET 요청(`/wp-json/wp/v2/users/me?context=edit`)으로만 연결을 시험했다.

**결과: HTTP 401 (`rest_not_logged_in`)** — 이 Application Password 자체가 WordPress에서 거부되고 있다. 이는 이번 세션에서 새로 발생한 문제가 아니라, 오늘 앞선 대화에서 Dell 서버 V1 컨테이너 내부의 안전한 GET 요청으로도 동일하게 확인했던 **기존 자격증명 문제**다(V1의 마이페이지 비밀번호 변경이 실패하는 원인과 동일). 코드 경로는 정상이며, WordPress 관리자 화면에서 Application Password를 재발급해야 실제 로그인 연동이 가능하다.

**실행하지 않은 것**: 실제 회원 비밀번호로 `authenticate()`를 호출하는 것(실제 회원 자격증명이 없어 테스트 불가하며, 운영 계정 잠금 위험을 피하기 위해 시도하지 않음), 신규 WordPress 사용자 생성.

## 남은 문제
- WordPress Application Password 재발급 필요(사용자가 WordPress 관리자 화면에서 처리해야 함, 코드 쪽 조치 아님)
- Google OAuth 클라이언트 ID는 이관됐으나 아직 로그인 화면에 연결하지 않음
- 이메일 인증·비밀번호 재설정 메일은 여전히 "개발 모드"로 화면에 링크를 직접 표시(SMTP 미연결, `config/.env`에 SMTP 항목은 있으나 값 확인 안 됨)
