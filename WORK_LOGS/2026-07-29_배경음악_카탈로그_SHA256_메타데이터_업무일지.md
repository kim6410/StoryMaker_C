# StoryMaker Claude Lab - 배경음악 카탈로그 업무일지

작성일시: 2026-07-29

작업 목적: 계획서 21번 지시사항에 따라 runtime/music/mp3(61개, 253,865,820 bytes) 원본의 메타데이터 카탈로그를 만든다. 파일은 옮기거나 이름을 바꾸지 않는다.

## 생성/수정 파일
- app/db/migrations.py: 마이그레이션 005(music_catalog 테이블: filename, relative_path, size_bytes, sha256, duration_seconds, codec, bitrate, sample_rate, duplicate_of_id)
- scripts/scan_music_catalog.py (신규): SHA-256 계산, ffprobe로 재생시간·코덱·비트레이트·샘플레이트 수집, 같은 해시는 duplicate_of_id로 표시(자동 삭제 안 함)
- app/content/music.py: 카탈로그 우선 조회로 전환(카탈로그가 비어 있으면 파일시스템 직접 조회로 폴백), 중복 항목은 기본적으로 목록에서 제외
- app/templates/content_new.html: 음악 선택 목록에 재생시간(mm:ss) 표시로 변경

## 실행 결과
- 카탈로그 스캔 스크립트 실행: 총 61개 mp3 파일 확인, 신규 61건 등록, 갱신 0건, 중복 후보 1건
- 중복 후보 1건 확인: mixkit-driving-ambition-32 (1).mp3 파일이 mixkit-driving-ambition-32.mp3 파일과 SHA-256 동일 -> 원본 파일명 그대로 두고 DB에서만 중복 표시(계획서 지시 "파일명을 바로 변경하지 말고" 준수)
- 전체 61곡 코덱 mp3, 비트레이트 256000, 샘플레이트 44100으로 확인(포맷 일관성 양호)

## 검증 결과
- 문법 검사 통과, 템플릿 파싱 통과
- 제작 입력 화면 실제 조회: 음악 옵션 60개(중복 제외) 노출, 재생시간 표기 정상(1background_music 2분46초 등)
- 기존 인증 회귀 테스트 13개 중 13개 통과 유지

## 남은 문제
- 중복 파일의 최종 삭제 여부는 사용자 승인이 필요함(현재는 보존, 목록에서만 숨김)
- 카탈로그는 수동 스캔 방식(파일이 추가되면 스캔 스크립트를 다시 실행해야 함, 자동 감시 아님)
