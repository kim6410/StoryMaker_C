# StoryMaker Claude Lab - 단계 5 업무일지

작성일시: 2026-07-29

작업 목적: 새 콘텐츠 제작 입력 화면을 마이페이지 업체 정보와 실제로 연결하고, 제작 요청 당시 스냅샷을 보존한다. 배경음악 라이브러리를 용량 중복 없이 연결한다.

## 설계 원칙 (계획서 참고, 가벼운 구조 우선)
- `content_jobs`를 별도 테이블로 새로 만들지 않고, 기존 `projects` 테이블에 필요한 컬럼만 추가했다(중복 개념 방지).
- 배경음악 61곡(mp3, 총 약 250MB 추정)을 프로젝트 `data/` 안으로 복사하지 않고 `runtime/music/mp3` 원본을 읽기 전용으로 그대로 스트리밍한다. 경로 조작 방지를 위해 파일명만 받아 라이브러리 폴더 내부로만 해석한다.
- 업체 정보 원본(마이페이지)과 제작 요청 당시 값을 분리했다 — `projects.input_snapshot_json`에 스냅샷을 저장하므로, 이후 마이페이지 업체 정보가 바뀌어도 이미 만든 작업의 내용은 변하지 않는다.
- 상태값을 계획서의 상태 머신(`draft → queued → prompting → generating → validating → content_ready → tts_ready → subtitle_ready → media_ready → rendering → completed`, 실패 시 `failed`)으로 갱신했다.

## 생성/수정 파일
- `app/db/migrations.py`: 마이그레이션 004(`projects`에 `company_id`, `input_snapshot_json`, `music_relative_path`, `voice_preference` 컬럼 추가)
- `app/db/repository.py`: `create_content_project`, `get_project_by_uid` 추가
- `app/constants.py`: 프로젝트 상태를 계획서 기준 12단계로 갱신
- `app/config.py`: `MUSIC_LIBRARY_DIR` 상수 추가(`runtime/music/mp3` 참조, 복사 없음)
- `app/content/music.py` (신규): 음악 목록 조회, 안전한 경로 해석
- `app/main.py`: `GET/POST /content/new`(실제 저장), `GET /content/job/{job_uid}`(상태 확인), `GET /content/music-preview/{filename}`(미리듣기 스트리밍)
- `app/templates/content_new.html`: 실제 업체 정보 프리필 + 실제 음악 목록 선택 + 미리듣기
- `app/templates/content_job_status.html` (신규): 스냅샷과 현재 상태 표시, Gemini 미설정 시 정직하게 안내

## 검증 결과
- `py_compile` 통과
- Python httpx로 로그인 → 제작 화면 조회(음악 목록 렌더 확인) → 제작 요청 생성 → 작업 상태 페이지에서 스냅샷 값 확인 완료
- 기존 인증 회귀 테스트 **13/13 PASS** 유지
- 테스트로 만든 작업·회원은 검증 후 정리함

## 참고: Gemini API 키 상태 변화
작업 도중 `config/.env`의 `GEMINI_API_KEY`가 (다른 세션에 의해) 채워진 것을 확인했다. 다만 이번 단계에서는 실제 Gemini 호출 코드는 아직 연결하지 않았다(계획서 단계 6 범위). 작업 상태 화면은 키 설정 여부를 실시간으로 감지해 안내 문구를 전환하도록 만들어 뒀다.
