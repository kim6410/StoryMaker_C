## 1단계: 정적 코드 조사 결과 요약

- `render-capabilities.js`의 `detectWebGPU()`는 `requestAdapter → requestDevice → 텍스처 생성 →
  렌더패스 실행`까지 실제로 수행하는 진짜 진단이다(단순 존재 체크 아님). 그러나 그 결과(`webgpu_ready`)는
  `localRenderReady` 판정식과 실제 프레임 렌더링(Canvas 2D만 사용) 어디에도 쓰이지 않는다 -
  "지원 여부는 정직하게 진단하지만 렌더링에는 실사용 안 함"으로 확인.
- WebCodecs(`VideoEncoder`/`AudioEncoder`)는 `local-renderer-worker.js`에서 실제 인코딩에 쓰인다(확인).
- WASM은 프로젝트 전체에 `.wasm` 파일이 없고 `mp4-muxer.min.js`(32KB, 순수 JS)에도 `WebAssembly` 문자열이
  0건 - 완전 미사용으로 확인.
- FFmpeg는 서버 폴백 경로(`generate_mp4_for_project`)에서만 전체 인코딩에 쓰인다. 단, 로컬 렌더 경로에서도
  사용자가 "영상"을 미디어로 선택하면 `_resolve_scene_images()`가 대표 프레임 추출을 위해 FFmpeg를 1회
  호출하는 숨은 예외를 발견(가벼운 프레임 추출이며 전체 인코딩은 아님).
- 서버 FFmpeg 동시 실행 제한이 코드 어디에도 없었다(`try_start_mp4_render`는 같은 프로젝트 중복 렌더만
  차단, 프로젝트 간 전역 제한 없음) - 요청서 7-3장 미충족 확인.
- UI 표기(`admin_diagnostics.html`)는 "WebGPU 지원 브라우저"로 정직하게 표시 중이라 과장 표시는 없었음.
- 진단 로그(`content_render_diagnostics`)에 `render_method`가 로컬 실패→서버 폴백 상황에서도 항상
  문자열 `"local"`로 고정 전송되는 버그성 이슈를 `local-render-controller.js`에서 발견.

## 수정한 파일

- `app/config.py` - `FFMPEG_MAX_CONCURRENT`(기본 2, 환경변수로 조정 가능) 추가
- `app/media/renderer.py` - `_run_ffmpeg()`를 `threading.Semaphore(FFMPEG_MAX_CONCURRENT)`로 감싸
  서버 FFmpeg 동시 실행을 전역 2개로 제한(초과 요청은 세마포어에서 대기). 장면 렌더·컨캣·오디오 믹스·
  썸네일 추출·프레임 추출·최종 mux 등 `_run_ffmpeg`를 쓰는 모든 호출부에 자동 적용됨
- `app/db/migrations.py` - migration 16(`render_diagnostics_expansion`) 추가:
  `content_render_diagnostics`에 `wasm_supported`, `server_ffmpeg_used`, `ffmpeg_elapsed_ms` 컬럼 추가
  (기존 컬럼·데이터는 그대로, 신규 컬럼만 0으로 채워짐)
- `app/static/js/render-capabilities.js` - `detect()` 반환값에 `wasmSupported`(`typeof WebAssembly !==
  "undefined"`, 지원 여부만이며 실사용 아님을 주석으로 명시) 추가
- `app/static/js/local-render-controller.js` - `reportDiagnostics()` 버그 수정: `outcome`이
  `fallback_success`/`fallback_failed`일 때 `render_method`를 `"server"`로, 그 외에는 `"local"`로 정확히
  구분해서 전송하도록 수정. `wasm_supported`, `server_ffmpeg_used` 필드 추가 전송
- `app/main.py` - `/content/job/{job_uid}/mp4/render-diagnostics` 라우트가 `wasm_supported`,
  `server_ffmpeg_used` 필드를 받아 저장하도록 확장
- `app/db/repository.py` - `save_render_diagnostics()` INSERT 문에 `wasm_supported`,
  `server_ffmpeg_used`, `ffmpeg_elapsed_ms` 컬럼 추가
- `app/media/service.py` - `generate_mp4_for_project()`(서버 FFmpeg 경로) 자체에도 소요시간을 측정해
  `content_render_diagnostics`에 남기는 `_log_server_ffmpeg_diagnostics()` 헬퍼를 추가하고, 성공 1곳과
  실패 5곳(장면렌더·컨캣·오디오믹스·mux·검증 실패) 총 6개 리턴 지점에 한 줄씩 호출을 삽입(기존 로직·
  리턴값·제어 흐름은 변경하지 않음, 순수 추가). 이 작업 중 해당 함수에 `user_id` 지역변수가 정의돼
  있지 않았던 것을 발견해 `project["user_id"]`로 정의를 추가함(내가 추가한 로깅 호출이 참조하기 위해
  필요했던 수정이며, 기존 동작에는 영향 없음)
