# 2026-07-29 단계11 보완 - 업로드 이미지 MP4 반영, 로컬렌더 자막 복구, 썸네일 템플릿

## 요청 배경

사용자가 대규모 지시서로 17개 항목을 요청. 이 업무일지는 그중 "최우선"으로 지정된
8번(업로드 이미지가 MP4 슬라이드쇼에 반영 안 됨), 9번(SRT 자막이 MP4에 안 나옴),
10번(썸네일에 업로드 이미지·템플릿 미적용), 11번(MP4·썸네일 공통 미디어 Context)
네 항목을 다룬다. 나머지 항목(글자색, Prompt, TTS 교차, 타임라인/렌더선택 UI 삭제)은
같은 세션의 다른 커밋에서 이미 처리했다.

## 원인 분석

- `create_content_job()`은 이미 `selected_media_ids`를 프로젝트 스냅샷에 저장하고
  있었지만(단계11 초반 커밋에서 추가), `generate_mp4_for_project()`와
  `build_scene_plan()`은 그 값을 전혀 읽지 않고 항상 `_PALETTE`의 그라디언트 색상만
  썼다 — 이미지 선택을 필수로 만든 뒤에도 실제 렌더러가 그 선택을 소비하지 않는
  "저장은 되지만 안 쓰이는" 상태였다.
- 서버 FFmpeg 렌더 경로는 원래부터 `SceneSpec.caption`으로 자막을 화면에 굽고
  있었지만(정상), 그 값을 DB `content_scenes`에는 저장하지 않았다. 그래서 로컬
  (WebCodecs/Canvas) 렌더용 `render-manifest.json`에는 자막 문장 자체가 아예
  빠져 있었다 — 로컬 렌더가 성공하는 사용자에게는 자막이 통째로 사라지는 문제였다
  (서버 렌더 사용자는 원래도 정상이었음).
- 썸네일은 완성된 MP4에서 8개 시점 프레임을 그냥 추출만 했다(텍스트 오버레이 없음).
  이미지 자체는 MP4가 그라디언트였으니 자동으로 그라디언트 썸네일이 나왔던 것이고,
  MP4 수정만으로도 썸네일 배경 문제는 자동 해결됨을 확인했다.

## V1·Beta 조사 결과 (포크로 병렬 조사)

- V1 소스코드는 이 PC에 없다(Docker 뒤 API로만 존재, TTS 백업 폴더뿐). 대신 로컬에
  실제 코드가 있는 Beta(`F:\StoryMaker_beta`)를 참고 기준으로 삼았다.
- Beta MP4: `clip_duration = max(1.5초, 전체길이/이미지수)`, `zoompan`으로 최대 1.08배
  완만한 확대, `scale=increase,crop`으로 9:16 채우기, 짧은 페이드인/아웃, concat demuxer로
  이어붙임. StoryMaker_C는 이미지 수가 아니라 TTS 문장 경계로 장면을 나누는 구조라
  이미지-장면 매핑만 그대로 가져오고(장면마다 이미지를 순서대로 배정, 이미지가 장면보다
  적으면 처음부터 반복), 표시시간/전환 로직 자체는 기존 문장 기반 구조를 유지했다
  (V1·Beta 흉내로 검증된 자막 동기화 엔진을 갈아엎지 않음).
- Beta의 SRT 번인: 서버(FFmpeg) 경로는 자막을 전혀 굽지 않고, 오직 브라우저 Canvas
  경로에서만 그린다(하단 안전영역, 반투명 박스, 흰 글자+검정 외곽선, 최대 3줄). 이
  원칙(굵은 글씨+검정 외곽선/그림자로 사진 위에서도 읽히게)은 그대로 계승했다.
- Beta 썸네일: "8종 서로 다른 템플릿"은 V1·Beta 어디에도 존재하지 않았다(Beta는
  사용자가 슬라이더로 조절하는 템플릿 1종뿐, 자동 생성은 텍스트 없는 단순 크롭).
  존재를 확인할 수 없는 걸 지어내지 않고, Beta가 실제로 쓰는 원칙(굵은 폰트+검정
  외곽선+그림자, 배경 어둡게, 안전영역)만 재구현했다. `F:\4종썸네일`이라는 별도
  React 프로토타입이 있었지만 V1·Beta와 무관한 별도 실험이라 참고하지 않았다.

## 구현

### DB 스키마
- 마이그레이션 14: `content_scenes.image_relative_path` 추가(빈 문자열이면 기존과
  동일하게 그라디언트).
- 마이그레이션 15: `content_scenes.caption` / `caption_start_local` / `caption_end_local`
  추가(로컬 렌더 매니페스트가 읽을 수 있도록). 마이그레이션 14가 이미 이 세션 중
  테스트 DB에 적용된 뒤였기 때문에, 14 내용을 고쳐 쓰지 않고 별도 15번으로 추가했다
  (마이그레이션은 한 번 적용되면 절대 재작성하지 않는다는 프로젝트 규칙 준수).

### 이미지 → MP4 슬라이드쇼 (`app/media/service.py`, `scene_planner.py`, `renderer.py`)
- `_resolve_scene_images(project, media_dir)`: 스냅샷의 `selected_media_ids`를
  실제 업체 미디어로 변환. 이미지는 그대로, 영상은 길이의 절반 지점에서 대표 프레임을
  뽑아 정지 이미지로 대신 사용(영상-슬라이드 합성 엔진을 새로 만들지 않고 기존 이미지
  장면 구조를 재사용 - 최소 수정 우선).
- `build_scene_plan()`에 `image_paths` 매개변수 추가, 장면마다 순서대로 이미지를
  배정(`SceneSpec.image_path`).
- `renderer.generate_scene_clip()`: `spec.image_path`가 있으면 그 사진을
  `scale=increase,crop`으로 9:16을 채워 배경으로 쓰고, 없으면 기존 그라디언트 그대로.
  기존 텍스트(상호·전화번호·자막) 오버레이 로직은 손대지 않음.
- 서버 렌더(`generate_mp4_for_project`)와 로컬 렌더 매니페스트 폴백
  (`build_render_manifest`) 양쪽 모두 같은 `_resolve_scene_images()`를 호출해
  MP4와 로컬 렌더가 서로 다른 이미지를 쓰지 않게 통일했다.

### 로컬(WebCodecs) 렌더 자막·이미지 복구
- `build_render_manifest()`의 `scenes` 목록에 `caption` / `caption_start_local` /
  `caption_end_local` / `image_url`을 추가.
- `GET /content/job/{job_uid}/mp4/scene-image/{scene_index}` 신규 라우트: 이 작업
  소유의 장면에 배정된 이미지 파일만 내려준다(소유권 확인, 잘못된 장면 인덱스는 404).
- `local-renderer-worker.js`: 프레임마다 fetch하면 느리므로 장면별 이미지를 시작 전에
  한 번씩만 fetch+`createImageBitmap`으로 미리 디코드해 캐시(`preloadSceneImages`).
  기존 그라디언트 채우기 자리에 `drawCoverImage()`(짧은 변 기준 확대 후 중앙 크롭)를
  넣고, 그 위에 기존 줌(자기 자신을 다시 그려 확대하는 방식)·자막·상호·전화번호 로직은
  그대로 재사용(변경 없음). 이미지 하나가 로딩 실패해도 그 장면만 그라디언트로
  대체하고 로컬 렌더 전체를 포기하지 않는다.

### 썸네일 템플릿 (`thumbnail_service.py`, `renderer.py`)
- `renderer.extract_thumbnail_candidate()`: 프레임 추출 시 배경을 살짝 어둡게
  (`eq=brightness=-0.08`) 하고, 굵은 헤드라인을 검정 외곽선(`borderw`)과 반투명
  박스로 얹는다. 8개 후보는 같은 스타일이고 추출 시점(장면)만 다르다 — 존재가
  확인되지 않는 "서로 다른 8개 레이아웃"을 지어내지 않았다.
- `_pick_thumbnail_headline()`: 쇼츠 채널 제목 → 네이버 블로그 제목 → 그 외 채널
  제목 → 제작 주제 순으로 헤드라인을 고른다.
- `_wrap_headline()`: FFmpeg drawtext에는 텍스트 폭 자동측정이 없어(Beta의
  `fitText`처럼 폰트를 동적으로 줄일 수 없음), 글자수 기준으로 최대 2줄까지 나누고
  넘치면 말줄임표로 축약 — 첫 구현(줄바꿈 없이 66px로 그대로 출력)에서 실제로 화면
  밖으로 글자가 넘치는 걸 스크린샷으로 확인하고 fontsize 66→52 + 2줄 래핑으로 수정.

## 검증 (포트 8033, 8032/8031 무관섭)

httpx E2E + 실제 파일 육안 확인(스크린샷으로 직접 확인, 파일 존재 여부만으로 PASS
처리하지 않음):

1. 새 업체를 만들고 눈에 띄는 **빨간 단색 테스트 사진**을 업로드해 선택 → 딸깍 제작
   → 채널 생성(실제 Gemini 1회 호출, 첫 시도 실패해 1회 재시도) → TTS(로컬
   Supertonic) → MP4(서버 FFmpeg) 전부 성공.
2. `content_scenes.image_relative_path`가 7개 장면 전부 업로드한 사진 경로로
   채워짐을 DB에서 직접 확인.
3. 완성된 MP4에서 3초 지점 프레임을 ffmpeg로 추출해 열어보니: **빨간 사진이 실제
   배경으로 나오고**(그라디언트 아님), 상호명·전화번호 배지, 자막("안녕하세요!")이
   모두 정상적으로 화면에 보임 — 스크린샷으로 직접 확인.
4. `render-manifest.json`을 직접 호출해 `image_url`·`caption`·
   `caption_start_local/end`가 채워져 있고, `image_url`을 실제로 GET하면 200과
   함께 이미지 바이트가 내려오는 것을 확인(로컬 렌더가 실제로 쓸 데이터 계약 검증,
   WebCodecs 인코딩 자체는 실제 브라우저 GPU 렌더가 필요해 이번 세션에서는 코드
   리뷰 + 데이터 계약 검증으로 대신함 - 아래 "남은 확인" 참고).
5. 신규 라우트 `/mp4/scene-image/{index}`가 존재하지 않는 장면(404)과 미로그인
   (로그인 페이지로 리다이렉트) 모두 올바르게 차단하는지 확인.
6. 썸네일 후보 생성 → 추출한 파일을 직접 열어 확인: 처음에는 헤드라인이 화면 밖으로
   넘쳐서(fontsize 66, 줄바꿈 없음) 즉시 fontsize 52 + 2줄 래핑으로 수정 → 재생성
   후 실제 빨간 사진 배경 + 상호·전화번호 + 2줄로 깔끔하게 래핑된 헤드라인을 스크린샷
   으로 확인. 대표 썸네일 선택(`thumbnail/select`)도 정상 동작 확인.
7. `scripts/db_selftest.py` 24/24 PASS(스키마 변경 2건 포함, 회귀 없음).

테스트에 쓴 임시 스크립트·이미지는 검증 후 삭제, 8033은 종료함. 8032는 건드리지 않음.
