## 1. 작업 목적

단계 7(TTS/SRT)은 영상용 원고가 DB에 정상 저장되어 있어야 시작할 수 있다. 6A는 단일 시험용 계약만 검증했으므로, 5장이 요구하는 최소 6B 범위(8채널 JSON 출력계약, 실제 응답 검증, 채널별 DB 저장, 숏폼 영상원고+장면문장 저장, 사용자별 격리, 결과 확인, 부분 재시도, 인증 회귀)를 구현했다.

## 2. DB 마이그레이션 007

`app/db/migrations.py`에 `_migration_007_channel_results` 추가, `schema_migrations`에 버전 7로 기록됨(적용 확인: `run_migrations() -> [7]`).

- `content_channel_results`: 채널별 결과 1행(제목/본문/해시태그/CTA + 원본 백업 컬럼 + `is_edited` + `status`). `(project_id, channel_code)` 유니크 인덱스로 채널당 최신 행 1개만 유지 — 재생성/수정/원복이 다른 7개 채널을 건드리지 않는 구조.
- `content_video_scripts`: 프로젝트당 1행(내레이션 원고 `voice_script` + 장면 문장 목록 `scene_sentences_json`). `project_id` 유니크.

기존 `content_generations`(호출 이력)/`content_generation_results`(6A 단일 계약, 하위호환용으로 테이블은 유지하되 이번 단계부터 새로 쓰지 않음) 테이블은 그대로 유지했다.

## 3. 프롬프트/검증 확장

- `app/ai/prompt_builder.py`: `build_channels_prompt()` — 네이버블로그/인스타그램/페이스북/당근마켓/네이버플레이스/구글비즈니스프로필/카카오채널/숏폼영상원고 8개 채널을 한 번의 Gemini 호출로 요청하는 프롬프트(채널마다 다른 스키마, `shortform_script`에만 `voice_script`+`scene_sentences` 요구). `build_single_channel_prompt()` — 채널 하나만 재생성할 때 쓰는 축소 프롬프트.
- `app/ai/schema.py`: `validate_channels_response()` — 8개 채널이 모두 존재하는지, 각 채널의 title/body/cta/hashtags(그리고 shortform_script는 voice_script/scene_sentences)가 비어있지 않고 길이 제한을 지키는지 검증. 기존 API 키·내부 경로 유출 검사에 더해 업체 정보의 `forbidden_words`(금지 표현)가 결과에 섞여 있는지도 검사(신규: `_forbidden_words_found`). 8개 중 하나라도 실패하면 전체를 실패 처리한다(작업지시 5장 "누락 슬롯만 보정 요청" 원칙에 따라, 부분 실패는 별도의 단일 채널 재생성 API로 처리). `validate_single_channel_response()` — 단일 채널 재생성 응답 검증.

## 4. 서비스 계층

`app/ai/service.py`:
- `generate_channels_for_project(project)` — 8채널 프롬프트로 1회 Gemini 호출 → 검증 → 8개 채널 UPSERT + 영상원고 UPSERT. 실패 시 `content_generations.status='failed'`로 남기고 채널 테이블은 건드리지 않는다(부분 저장 금지).
- `regenerate_channel_for_project(project, channel_code)` — 채널 하나만 재생성. 성공 시 그 채널(과 `shortform_script`인 경우 영상원고)만 UPSERT.
- `_build_context()`를 확장해 업체 정보의 `core_strength`/`forbidden_words`를 제작 스냅샷에 없으면 최신 업체 레코드(`companies` 테이블)에서 보완하도록 했다(금지 표현 가드레일은 스냅샷이 아니라 최신 설정을 따르는 것이 안전).

## 5. 라우터/화면

`app/main.py`:
- `POST /content/job/{job_uid}/generate` — 이제 8채널 생성을 호출하고, 성공 시 `/content/job/{job_uid}/channels`로 이동한다.
- `GET /content/job/{job_uid}/channels` — DB에 저장된 8채널 결과와 영상원고(장면 문장 목록 포함)를 실제로 읽어 표시한다(샘플 데이터 아님). 소유권 검사는 기존 `_get_owned_project_or_none()` 재사용.
- `POST /content/job/{job_uid}/channels/{channel_code}/regenerate` — 채널 하나만 재생성.
- `POST /content/job/{job_uid}/channels/{channel_code}/edit` — 채널 부분 수정, `is_edited=1` 기록.
- `POST /content/job/{job_uid}/channels/{channel_code}/revert` — 원본으로 되돌리기.

신규 템플릿 `app/templates/content_job_channels.html` 추가. 기존 `content_job_status.html`은 생성 버튼 문구를 8채널 기준으로 바꾸고, 생성 완료 후 채널 결과 페이지로 가는 링크를 추가했다(기존 단일 계약 표시 블록은 제거).

기존 샘플 전용 `/content/channels`(작업과 무관한 데모 페이지, `SAMPLE_CHANNELS`)는 건드리지 않고 그대로 남겨뒀다.
