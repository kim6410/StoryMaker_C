# StoryMaker_C 클로드 작업 중간평가

작성일: 2026-07-29

작업 대상: `F:\StoryMaker_C`

평가 목적: Windows 환경에서 Claude가 새로 구축한 StoryMaker_C 웹앱의 현재 구조, 엔진, 데이터베이스, 테스트, 운영 준비 수준을 중간 점검하고 이후 개발 우선순위를 정리한다.

---

## 1. 종합 결론

StoryMaker_C는 더 이상 화면만 있는 샘플 웹앱이 아니다.

현재는 회원, 업체, 콘텐츠 작업, SNS 8채널, TTS, SRT, MP4, 썸네일, 보관함, 구독·사용량, 관리자 기능을 모두 연결하려는 실제 제작 파이프라인을 갖춘 **알파 후반~베타 초반 단계의 제품**이다.

전체 구조를 다시 만들 필요는 없다. DB와 도메인별 모듈 구조는 유지하고, 현재 끊겨 있는 미디어 데이터 흐름과 실제 결과물 품질을 보완한 뒤 큰 파일을 점진적으로 분리하는 방향이 가장 안전하다.

### 종합 완성도

**약 70%**

엄격하게 평가하면 다음과 같다.

| 평가 영역 | 완성도 | 평가 |
|---|---:|---|
| 화면·사용자 흐름 | 82% | 상당히 잘 잡힘 |
| 업체·회원·보관함 구조 | 80% | 실제 서비스 기반 수준 |
| DB 구조와 무결성 | 85% | 현재 가장 안정적인 영역 |
| Gemini SNS 8채널 엔진 | 65% | 동작하지만 품질 정합성 보완 필요 |
| TTS·SRT 엔진 | 62~65% | 구조는 있으나 실제 결과 검증 부족 |
| MP4 슬라이드쇼 엔진 | 55% | 핵심 미완성 영역 |
| 썸네일 엔진 | 55% | 구조는 있으나 Beta 수준 도달 전 |

| 배포·운영 준비 | 55% | 로컬 베타는 가능, 상용 운영은 이른 단계 |

### 구조적 장점

- AI, 인증, 콘텐츠, DB, TTS, 자막, 미디어가 도메인별로 분리되어 있다.
- Gemini 호출부가 `integrations` 계층으로 분리되어 있다.
- 영상 장면 계획과 실제 렌더링 책임이 나뉘어 있다.
- SRT 생성기가 별도 모듈이다.
- 로컬 브라우저 렌더 Worker와 서버 렌더 경로를 함께 고려했다.
- 단순 임시 코드가 아니라 실제 제품 구조를 의식한 설계다.

### 가장 큰 구조적 약점

```text
app/main.py             약 1,699줄
app/db/repository.py    약 1,645줄
```

두 파일에 책임이 지나치게 집중되어 있다.

당장은 작동하더라도 기능이 늘어날수록 수정 범위가 커지고 회귀 가능성이 높아진다.

출시 전에는 다음과 같이 점진적으로 분리하는 것이 바람직하다.

```text
app/routes/
├─ dashboard.py
├─ companies.py
├─ content.py
├─ archive.py
├─ mypage.py
└─ admin.py

app/db/repositories/
├─ user_repository.py
├─ company_repository.py
├─ content_repository.py
├─ media_repository.py
├─ archive_repository.py
├─ subscription_repository.py
└─ audit_repository.py
```

단, 지금 즉시 전면 리팩터링하는 것은 위험하다. 핵심 제작 흐름 안정화 후 최소 단위로 분리해야 한다.

## 3. 데이터베이스 평가

DB는 현재 StoryMaker_C에서 가장 안정적인 영역이다.

실제 실행 결과:

```text
DB selftest: 24/24 PASS
```

검증된 항목:

- 마이그레이션 1~14 적용
- 플랜 생성 및 조회
- 사용자 생성·조회·상태 변경
- 구독 연결
- 프로젝트 생성 및 상태 변경
- 보관함 저장과 소프트 삭제
- 감사로그 저장과 보존
- 사용자 삭제 시 프로젝트·보관함 연쇄 삭제
- SQLite integrity check
- foreign key check
- WAL 모드
- 20개 스레드 동시 쓰기

핵심 결과:

```text
integrity_check = ok
foreign_key_check = 문제 없음
journal_mode = wal
20개 동시 쓰기 = 오류 없음
```

### DB 장점

- 마이그레이션 버전 관리가 존재한다.
- 외래키를 사용한다.
- WAL과 동시 쓰기를 고려했다.
- 감사로그가 존재한다.
- 플랜·구독·회원·프로젝트·보관함 구조가 분리되어 있다.
- 사용자별 데이터 격리를 고려했다.

### DB 보완점

DB 설계 자체보다 접근 계층이 과도하게 비대하다.

`repository.py`를 향후 도메인별 Repository로 분리해야 한다.

평가:

- DB 설계: 85점
- DB 접근 코드 구조: 65점

## 4. Gemini SNS 8채널 엔진 평가

확인된 구조:

```text
app/ai/prompt_builder.py
app/ai/schema.py
app/ai/service.py
app/integrations/gemini_client.py
```

구조적 흐름은 적절하다.

```text
업체·사용자 입력
→ Prompt Builder
→ Gemini Client
→ 구조화 응답 검증
→ 채널별 결과 저장
```

### 장점

- AI 호출과 Prompt 생성, Schema 검증이 분리되어 있다.
- 업체 페르소나를 Prompt에 반영하는 구조가 있다.
- SNS 8채널 슬롯과 결과 저장 흐름이 있다.

### 현재 문제

V1·Beta에서 사용하던 실제 Prompt와 차이가 있어 채널별 결과 품질과 형식이 다르다.

따라서 엔진 자체는 존재하지만 StoryMaker의 핵심 콘텐츠 노하우는 아직 완전히 복구되지 않았다.

현재 평가:

- AI 호출 엔진: 75%
- 실제 채널 콘텐츠 품질 포함: 65%

## 6. SRT 자막 엔진 평가

확인된 구조:

```text
app/subtitle/srt_builder.py
```

SRT 생성 책임이 별도 모듈로 분리된 점은 좋다.

그러나 실제 최종 MP4에서 자막이 보이지 않는 문제가 있다.

가능한 단절 구간:

```text
TTS 문장 및 시간

→ 렌더 Manifest

→ 최종 MP4 자막 번인
```

SRT 생성 자체보다 최종 영상 연결이 핵심 문제다.

평가:

- SRT 생성 모듈: 70%
- 최종 결과 포함: 55~60%

## 7. MP4·슬라이드쇼 엔진 평가

확인된 주요 구성:

```text
app/media/service.py
app/media/renderer.py
app/media/scene_planner.py
app/media/ffprobe_utils.py
app/static/js/local-render-controller.js
app/static/js/local-renderer-worker.js
app/static/vendor/mp4-muxer.min.js
```

### 기술적 장점

- 브라우저 로컬 렌더와 서버 폴백을 모두 고려했다.
- TTS PCM 처리 구조가 있다.
- 배경음악 믹싱과 페이드 처리가 있다.
- AAC 인코딩과 MP4 muxing 구조가 있다.
- WebCodecs 기반 Worker를 사용한다.
- 장면 계획 로직을 별도 모듈로 분리했다.

### 핵심 문제

업로드 또는 선택한 이미지가 실제 MP4 슬라이드쇼에 반영되지 않는다.

핵심 데이터 흐름 중 일부가 끊겨 있을 가능성이 크다.

```text
업로드 이미지
→ 작업 미디어 DB
→ ordered media
→ scene planner
→ renderer
→ MP4
```

코드 구조만 보면 75% 수준이나 실제 사용자 결과 기준으로는 55%다.

현재 전체 완성도를 가장 많이 낮추는 영역이다.

## 12. Git 상태 평가

평가 시점 기준 기존 커밋의 로컬 HEAD와 GitHub `origin/main`은 일치했다.

```text
a7236192de666cce0b2db814ff8b64f8bdbcbf0c
```

그러나 2026-07-29에 진행한 UI, 미디어, TTS, DB 관련 추가 수정은 아직 커밋되지 않은 상태였다.

즉:

```text
기존 커밋: GitHub와 일치

```

다음 큰 작업 전에 현재 변경분을 검증하고 선별 커밋·Push하는 것이 필요하다.

## 13. 현재 가장 중요한 미완성 항목

전체 완성도를 제한하는 핵심 항목은 다음 네 가지다.

1. 업로드 이미지가 최종 MP4 슬라이드쇼에 제대로 연결되지 않음
2. SRT가 최종 MP4 화면에 나타나지 않음
3. 남녀 TTS 교차가 실제 오디오에서 정상 적용되지 않음
4. 썸네일이 작업 이미지와 템플릿을 제대로 사용하지 않음

이 네 가지는 모두 최종 산출물 품질에 직접 영향을 준다.

## 14. 다음 개발 우선순위

권장 순서:

```text

```

이 순서로 진행하면 현재 약 70%인 완성도를 88~92% 수준까지 올릴 수 있다.

## 15. 최종 판정

StoryMaker_C는 전체를 다시 만들 정도로 잘못된 프로젝트가 아니다.

현재 상태는 다음과 같다.

```text
관리 웹앱 완성도: 높음
제작 파이프라인 구조: 높음
실제 미디어 결과물 완성도: 중간
```
