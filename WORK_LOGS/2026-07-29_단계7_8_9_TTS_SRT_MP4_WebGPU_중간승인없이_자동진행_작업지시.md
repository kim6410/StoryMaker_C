# StoryMaker_C 단계 7~9 자동 진행 작업지시

작성일: 2026-07-29

## 1. 목적

사용자가 자리를 비우는 동안 중간 승인 없이 단계 7~9를 순서대로 진행한다.

단, 검증을 생략하거나 억지로 완료 처리하지 않는다.

각 단계의 완료 기준을 통과해야 다음 단계로 넘어간다.

작업 루트는 오직 `F:\StoryMaker_C`다.

최우선 기준은 다음 문서다.

- `F:\StoryMaker_C\00_READ_FIRST.md`
- `F:\StoryMaker_C\WORK_LOGS\2026-07-29_단계5이후_딸깍콘텐츠_AI_TTS_SRT_MP4_WebGPU_WASM_전체완주_상세계획.md`
- `F:\StoryMaker_C\WORK_LOGS\2026-07-29_단계6A_Gemini_프롬프트생성기_실API호출_검증_작업지시.md`

## 2. 중간 승인 없이 진행해도 되는 범위

- 현재 단계에 필요한 코드 작성과 수정
- DB 마이그레이션 추가
- 단위 테스트와 E2E 테스트
- 서버 재기동
- 작업용 산출물 생성
- 관련 업무일지 작성
- 관련 파일만 선별 커밋
- Push
- 로컬 HEAD, origin/main, GitHub main 해시 검증

## 3. 반드시 중단하고 보고해야 하는 조건

다음 중 하나라도 발생하면 임의로 강행하지 않는다.

1. 기존 정상 기능을 대규모로 다시 작성해야 하는 경우
2. DB, 회원정보, 사용자 콘텐츠 또는 원본 파일을 삭제해야 하는 경우
3. 실제 결제, 유료 API 과금 확대, 운영 회원에게 영향을 주는 경우
4. API 키 또는 외부 서비스 인증이 불가능한 경우
5. V1·Beta 원본을 수정해야 하는 경우
6. 데이터 손상, 보안 취약점, 개인정보 노출 위험이 발견된 경우
7. `git reset --hard`, `git clean`, 강제 Push 등 파괴적 명령이 필요한 경우
8. 사용자의 새로운 정책 결정이 없으면 구현할 수 없는 경우

그 외의 세부 선택은 가장 단순하고 안전한 방향으로 판단해 계속 진행한다.

## 4. 공통 개발 원칙

- V1·Beta 업무일지와 소스는 시행착오와 개념 참고만 허용한다.
- 기존 코드를 복사하거나 일부만 바꿔 재사용하지 않는다.
- 기존 DB, 서비스, 포트, Worker, 가상환경을 런타임에서 직접 재사용하지 않는다.
- DB 접근은 Repository 계층을 사용한다.
- 외부 서비스는 Adapter 계층을 사용한다.
- API 키, 전체 프롬프트, 개인정보, 전체 원문 응답은 일반 로그에 남기지 않는다.
- DB에는 프로젝트 기준 상대경로만 저장한다.
- 단계별 산출물을 재사용하고 실패한 단계부터 다시 시작한다.
- 작업 ID별 잠금으로 중복 실행을 차단한다.
- `git add .`, `git add -A`는 사용하지 않는다.
- 테스트하지 않은 항목을 완료라고 보고하지 않는다.

## 5. 선행 조건

단계 7은 영상용 원고가 DB에 정상 저장되어 있어야 시작할 수 있다.

현재 단계 6A만 완료되고 8채널 결과와 영상 원고 저장이 없다면, 단계 7 전에 최소 6B를 먼저 수행한다.

최소 6B 범위:

- Gemini SNS 8채널 JSON 출력 계약
- 실제 응답 검증
- 채널별 DB 저장
- 숏폼 영상용 원고와 장면 문장 목록 저장
- 사용자별 데이터 격리
- 화면 또는 API에서 결과 확인
- 실패 상태와 부분 재시도
- 기존 인증 회귀 테스트

이 선행 범위는 별도 승인 없이 진행한다.

# 단계 7: TTS와 SRT 완주

## 목표

Gemini가 생성한 영상용 원고를 문장·장면 단위로 TTS 음성으로 만들고, 실제 음성 길이에 맞는 SRT를 생성한다.

## 구현 요구사항

### 영상 원고 정규화

- 영상용 원고를 장면과 문장 단위로 분리한다.
- 빈 문장을 제거한다.
- 지나치게 긴 문장은 분할한다.
- 숫자, 전화번호, 영어, 특수기호 읽기 규칙을 적용한다.
- `[여성]`, `[남성]` 같은 화자 표시는 자막에서 제거한다.
- 원본 원고와 TTS용 정규화 원고를 분리 저장한다.

### TTS Adapter

- StoryMaker_C 전용 TTS Adapter를 구현한다.
- 기존 V1·Beta 실행 중 서비스에 직접 의존하지 않는다.
- 프로젝트 내부 설정에서 엔드포인트와 모델을 관리한다.
- 화자, 속도, 톤, 문장 사이 쉼을 설정할 수 있게 한다.
- 문장별 음성을 생성한다.
- 실패한 문장만 재생성할 수 있게 한다.
- timeout, 연결 실패, 잘못된 응답, 빈 음성 파일을 구분한다.
- 무한 재시도를 금지한다.

### 산출물

작업 ID별로 다음을 분리 저장한다.

- 문장별 원본 WAV
- 전체 연결 음성 WAV
- 음성 메타데이터
- 문장별 실제 재생시간
- 생성 상태와 오류코드

### SRT 생성

- 글자 수 비율로 시간을 임의 분배하지 않는다.
- 문장별 실제 음성 길이를 ffprobe로 측정한다.
- 문장 사이 쉼 시간을 반영한다.
- 누적 시작·종료 시각을 계산한다.
- 한 줄 길이와 줄 수를 제한한다.
- 전체 음성 길이와 마지막 SRT 종료시각을 비교한다.
- 허용 오차를 명시하고 초과하면 실패 처리한다.
- 기존 정상 SRT가 있으면 불필요하게 덮어쓰지 않는다.

## 단계 7 완료 기준

- 실제 TTS 음성 생성 성공
- 문장별 WAV와 전체 WAV 재생 가능
- 길이 0초 파일 없음
- 실패 문장 부분 재시도 성공
- SRT 파싱 성공
- SRT 마지막 종료시각과 음성 길이 일치
- 화자 표시 제거 확인
- 다른 사용자 파일 접근 차단
- 서버 재시작 후 상태 유지
- 인증 E2E 회귀 테스트 통과
- DB integrity_check `ok`
- 업무일지 작성
- 관련 파일만 커밋·Push
- 세 해시 일치

# 단계 8: 배경음악·장면·FFmpeg MP4 완주

## 목표

TTS 음성, SRT, 이미지·영상, 배경음악을 결합해 정상 재생되는 9:16 H.264/AAC MP4를 생성한다.

## 배경음악

음악 라이브러리는 반드시 아래 경로만 사용한다.

`F:\StoryMaker_C\runtime\music\mp3`

- 외부 Beta 경로 직접 참조 금지
- `music_catalog` 상대경로 사용
- 파일 존재와 해시 확인
- 음성보다 음악이 작게 들리도록 기본 볼륨 설정
- 필요하면 Ducking 적용
- 시작·종료 페이드 적용
- 영상보다 짧으면 안전하게 반복 또는 종료 처리
- 영상보다 길면 자연스럽게 자르기
- 원본 MP3 수정 금지
- 작업용 변환본과 최종 혼합 음원 분리 저장
- 최종 MP4는 반드시 최종 혼합 음원을 사용

## 이미지·영상 정규화

- 실제 MIME 검사
- 손상 여부 확인
- 회전 메타데이터 반영
- 해상도와 프레임레이트 통일
- 영상 코덱 검사
- 너무 긴 영상 구간 제한
- 원본과 렌더용 변환본 분리
- 작업 ID 내부 상대경로 사용

## 장면 타임라인

각 장면에 다음을 저장한다.

- 소스 파일
- 시작시각
- 종료시각
- 표시시간
- 자막 문장
- 전환 방식
- 줌 시작값과 종료값
- 중심점 또는 이동 방향

장면 경계는 가능하면 음성 문장 경계와 맞춘다.

## 화면 효과

안정적인 프리셋으로 제한한다.

- 페이드
- 크로스 디졸브
- 슬라이드
- 천천히 줌인
- 천천히 줌아웃
- 약한 좌우·상하 이동

모든 장면에 과도한 효과를 넣지 않는다.

## FFmpeg 렌더

프로젝트 내부 FFmpeg와 ffprobe만 사용한다.

권장 출력:

- 1080×1920
- H.264
- AAC
- 30fps
- yuv420p
- faststart

렌더 순서:

1. 미디어 정규화
2. 장면별 줌·이동
3. 장면 전환
4. SRT 자막 오버레이
5. 상호·전화번호 오버레이
6. 최종 혼합 음원 결합
7. MP4 출력
8. ffprobe 검증

## 자막과 업체 정보

- 자막은 화면 하단 안전영역에 배치한다.
- 모바일에서 읽을 수 있는 크기를 사용한다.
- 흰색 글자와 충분한 검은 외곽선 또는 음영을 적용한다.
- 상호와 전화번호는 하단 중앙 또는 별도 안전영역에 둔다.
- 업체명이 자막을 가리지 않게 한다.

## 실패 복구

- 콘텐츠, TTS, SRT가 정상이면 재사용한다.
- MP4 실패 시 Gemini와 TTS를 다시 호출하지 않는다.
- 실패한 렌더 단계부터 재시도한다.
- 중복 렌더를 잠금으로 차단한다.
- 서버 재시작 후 processing 작업을 복구한다.

## 단계 8 완료 기준

- 실제 MP4 생성 성공
- 브라우저와 일반 플레이어에서 재생
- H.264/AAC 확인
- 해상도와 프레임레이트 확인
- 음성과 자막 싱크 확인
- 배경음악 포함 확인
- 음성 명료도 확인
- 검은 화면과 0초 영상 없음
- 장면 전환과 줌 효과 확인
- 상호·전화번호 표시 확인
- 다른 사용자 접근 차단

# 단계 9: WASM·WebGPU·WebCodecs 로컬 가속

## 목표

지원되는 사용자 브라우저에서 로컬 CPU·GPU 자원을 활용해 서버 부하를 줄이는 선택형 렌더 경로를 구현한다.

서버 FFmpeg 렌더는 항상 최종 폴백으로 유지한다.

## 기능 감지

다음을 각각 검사한다.

- WebGPU
- WebCodecs VideoEncoder
- WebCodecs AudioEncoder
- OffscreenCanvas
- WebAssembly
- SharedArrayBuffer 사용 가능 여부
- 예상 메모리
- 브라우저와 GPU 정보의 안전한 범위

미지원이면 오류로 끝내지 않고 서버 렌더로 안내한다.

## 로컬 렌더 흐름

1. 서버가 검증된 작업 명세 JSON 제공
2. 브라우저가 허용된 미디어만 다운로드
3. WebGPU 또는 Canvas로 프레임 생성
4. 줌·전환·자막·상호 오버레이
5. WebCodecs로 비디오 인코딩
6. Web Audio 또는 WASM으로 오디오 처리
7. MP4 컨테이너 조립
8. 결과 검증
9. 사용자 승인 후 서버 보관함 업로드

## 보안

- 서버가 작업 ID와 사용자 소유권을 검사한다.
- 임의 로컬 경로 접근을 금지한다.
- 허용된 미디어 URL만 사용한다.
- 업로드 파일 크기를 제한한다.
- 결과 MIME과 코덱을 검증한다.
- 다른 사용자 작업 명세 접근을 차단한다.
- 브라우저가 임의로 completed 상태를 기록하지 못하게 서버가 재검증한다.

## 사용자 경험

- 로컬 가속 사용 여부 선택
- 지원 상태 표시
- 예상 메모리와 주의사항 안내
- 렌더 진행률
- 현재 단계 표시
- 취소 기능
- 탭 종료 시 중단될 수 있다는 안내
- 실패 시 서버 렌더 전환 버튼
- 저사양 PC에는 서버 렌더 기본 권장

## 폴백 조건

다음 상황에서는 서버 렌더로 전환한다.

- WebGPU 미지원
- Encoder 미지원
- GPU device lost
- 메모리 부족
- 인코딩 오류
- 탭 새로고침
- 브라우저 백그라운드 중단
- 결과 검증 실패

## 단계 9 완료 기준
