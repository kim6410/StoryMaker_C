### 원인 분석

네 가지 핵심 문제 모두 "데이터는 저장되지만 다음 단계가 그 값을 읽지 않는" 유형의
단절이었다.

1. **이미지 미반영**: `selected_media_ids`는 이미 프로젝트 스냅샷에 저장되고 있었지만
   `generate_mp4_for_project()`/`build_scene_plan()`이 그 값을 전혀 읽지 않고 항상
   그라디언트 팔레트만 썼다.
2. **자막 미반영(로컬 렌더만)**: 서버 FFmpeg 경로는 원래부터 정상 작동했다(메모리 상의
   `SceneSpec.caption`을 바로 drawtext에 사용). 문제는 그 값을 DB에 저장하지 않아서
   로컬(WebCodecs) 렌더용 `render-manifest.json`에는 자막이 아예 없었던 것.
3. **TTS 단일 음성**: `synthesize_sentence()`가 프로젝트 전체에 하나의 `voice_preference`
   만 적용했다. 문장별로 다른 음성을 배정하는 로직 자체가 없었다.
4. **썸네일 무템플릿**: MP4에서 프레임만 그대로 추출했다. MP4가 그라디언트였으니
   썸네일도 자동으로 그라디언트였고, 텍스트 오버레이 로직 자체가 없었다.

### V1·Beta Prompt 위치와 구조

- **V1 원본은 이 PC에서 찾지 못했다.** 실제 프롬프트는 `http://127.0.0.1:8011/api/generate-prompt`
  라는 별도 실행 서비스(Docker로 추정)가 생성하며, `F:\StoryMaker_V1` 로컬 폴더에는
  Supertonic TTS 백업만 있고 웹앱 소스 자체가 없다. 전체 드라이브 재귀 검색도 시간
  초과로 원본을 확보하지 못했다 — 이 사실을 숨기지 않고 그대로 보고한다.
- **Beta**(`F:\StoryMaker_beta\app\beta_gemini.py`)도 자체 프롬프트가 없고 V1의 8011 API를
  그대로 호출한 뒤 "Beta 8채널 저장 어댑터"라는 짧은 텍스트만 붙인다. 이번에 실제로
  확보한 유일한 원문이 이 어댑터이며, 여기서 서사 구조(고객불편→현장확인→원인진단→
  작업과정→작업후확인), 날씨/시간대 절제 규칙, 채널별 정량 글자수를 확인했다.
- Beta의 실제 8채널(BLOG/NAVER_PLACE/GOOGLE_BUSINESS/INSTAGRAM/CARROT/CAROUSEL_7/
  PODCAST_50/PODCAST_80)은 StoryMaker_C 8채널과 이름이 다르다. 지시서의 "실제 채널명이
  다르면 현재 시스템 값을 기준으로 한다"에 따라 StoryMaker_C 자체 채널 정의를 유지했다.

### StoryMaker_C 기존 Prompt 문제

- 서사 구조 지시가 없어 본문이 정해진 흐름 없이 작성될 수 있었다.
- 날씨·시간대를 본문 중심으로 확장하지 말라는 절제 규칙이 없었다.
- 채널별 글자수가 "채널 성격에 맞는 길이"처럼 정성적으로만 서술돼 실제 편차가 클 수 있었다.
- (이 세 가지 외의 안전장치 - 프롬프트 인젝션 방어, 데이터/지시 분리, 빈 필드 금지,
  채널 간 복사 금지 - 는 이미 잘 갖춰져 있어 그대로 유지했다.)

### 수정한 Prompt (`app/ai/prompt_builder.py`)

- 시스템 규칙에 5단계 서사 구조와 날씨/시간대 절제 규칙 추가.
- `_CHANNEL_WRITING_RULES`로 8채널 각각의 정량 글자수·문체 규칙을 정의해
  `_channel_slot_schema()`에 주입: 블로그 1500~2000자, 인스타 250~450자, 페이스북
  400~700자, 당근 300~600자, 플레이스/구글 150~350자, 카카오 150~300자, 숏폼은
  TTS 적합 구어체+3초 후킹+문제→과정→해결→CTA 구조.
- 기존 안전장치·파서(엄격 JSON)는 변경하지 않음.

### SNS 8채널 결과 개선

Mock 테스트(25개 항목, Gemini 미호출)로 확인: 8채널 전부 포함, 채널별 정량 글자수
규칙이 서로 다르게 반영, 업체 페르소나·필수포함·자유요청·지역키워드 전부 포함,
서사구조·날씨절제·복사금지·인젝션방어 규칙 유지, 프롬프트 길이 4,148자로 과도하지 않음.
이후 실제 Gemini 1회 호출로 8채널 전부 title/body가 채워진 것을 DB에서 직접 확인.

### 결과 화면 글자색 수정

`/content/job/{uid}` SNS 8채널 결과 입력칸이 옅은 회색 글자 + 흰 배경으로 거의 안
보이던 문제를 `.channel-edit-form` 전용 CSS로 수정(진한 남색 글자, placeholder는
중간 회색, focus 시 파란 테두리+그림자). 탭 대비, 저장/복사 버튼 시각적 우선순위도
함께 개선. 정적 HTML 스냅샷을 실제 stylesheet와 함께 브라우저로 렌더링해 스크린샷으로
직접 확인.

### TTS 여성·남성 교차 적용

`_voice_preference_for_sentence(i)`: 짝수 인덱스(0,2,4...)=여성(F1), 홀수=남성(M1).
실제 8문장/10문장 생성 테스트에서 `['F1','M1','F1','M1',...]` 정확히 교차되는 것을
DB에서 확인. 단일 문장 재생성(`regenerate_tts_sentence`)도 같은 규칙을 적용해 재시도
시에도 음성이 바뀌지 않음을 확인. 사용자 화면의 "음성 화자" 선택 드롭다운은 제거하고
"음성은 여성·남성이 자동으로 교차 적용됩니다" 안내만 남김.

### 문장별 타임라인 삭제

`content_job_status.html`에서 초록/빨강 구간 막대 시각화 블록만 제거. 문장별 음성
테이블(상태·재생·재시도 버튼)은 실질적 기능이라 유지. SRT/TTS 타이밍 계산, MP4 합성
로직은 전혀 건드리지 않음.

### 렌더 방식 선택 UI 삭제

"내 PC에서 빠르게 만들기"/"서버에서 안정적으로 만들기" 두 카드와 버튼을 "영상 만들기"
버튼 하나로 통합. 기존 `StoryMakerLocalRender.startLocalRender()`가 이미 내부적으로
로컬 우선 시도 → 실패 시 자동 서버 폴백을 구현하고 있었으므로, UI만 하나로 합치고
그 함수를 그대로 재사용했다. 실패 시 표시 문구도 "영상 제작 방식을 자동으로
전환했습니다"로 기술 용어 없이 안내. 로컬/서버 엔진 자체는 전혀 삭제하지 않음.

### MP4 슬라이드쇼 이미지 연결

`_resolve_scene_images()`가 스냅샷의 `selected_media_ids`를 실제 업체 미디어로
변환(영상은 중간 지점 프레임을 추출해 정지 이미지로 대체). `build_scene_plan()`이
장면마다 순서대로 이미지를 배정하고, `renderer.generate_scene_clip()`이 이미지가
있으면 `scale=increase,crop`으로 9:16을 채워 배경으로 사용(없으면 기존 그라디언트
그대로). 서버 렌더와 로컬 렌더 매니페스트 양쪽이 같은 `_resolve_scene_images()`를
호출해 서로 다른 이미지를 쓰지 않게 통일했다.

### SRT 자막 복구

서버 FFmpeg 경로는 원래부터 정상이었음을 재확인. 로컬 렌더용으로 `content_scenes`에
`caption`/`caption_start_local`/`caption_end_local`을 새로 저장하고
`render-manifest.json`에 포함시켰다. `local-renderer-worker.js`는 원래도 이 필드가
있으면 자막을 그리는 로직(하단 안전영역, 반투명 박스, 흰글자+검정외곽선, 최대 2줄)이
이미 있었는데 데이터가 안 왔을 뿐이었다 — 데이터만 연결하면 되는 문제였다.

### 썸네일 이미지·템플릿 복구

**"V1·Beta의 8종 서로 다른 템플릿"은 실제로 존재하지 않았다** — 조사 결과 Beta는
사용자가 슬라이더로 조절하는 템플릿 1종뿐이고, 자동 생성 경로는 텍스트 없는 단순 크롭
이었다(`F:\4종썸네일`이라는 별도 React 프로토타입이 있었지만 V1·Beta와 무관). 존재를
확인 못 한 걸 지어내지 않고, Beta가 실제로 쓰는 원칙(굵은 글씨+검정 외곽선+그림자,
배경 어둡게, 텍스트 안전영역)만 재구현했다: `extract_thumbnail_candidate()`가 배경을
살짝 어둡게 하고, 우선순위(쇼츠 제목>블로그 제목>기타 채널 제목>제작 주제)로 고른
헤드라인을 글자수 기준 2줄 래핑(`_wrap_headline`)해 얹는다. MP4가 실제 이미지를 쓰게
되면서 썸네일도 자동으로 실제 이미지를 배경으로 쓰게 됐다(같은 MP4 프레임에서 추출).

  로컬 방식으로 끝까지 성공하는 케이스는 사용자 실사용 검증이 필요하다.
- V1의 실제 프롬프트 원문을 확보하지 못해, 이번에 반영한 채널별 글자수 중 일부
  (인스타/페이스북/카카오/숏폼)는 Beta 어댑터가 아니라 지시서 4장의 설명을 근거로
  새로 정한 값이다. V1 원본을 확인할 방법(Dell 서버 등)이 생기면 재검토 권장.
- 영상(동영상)을 미디어로 선택했을 때의 "중간 프레임 추출" 방식은 이번 E2E에서 실제로
  1개 영상으로 검증했지만(40초 지점 프레임에서 보라색 확인), 다양한 실제 촬영 영상
  포맷(세로/가로, 다양한 코덱)에 대한 폭넓은 테스트는 하지 못했다.
