# 2026-07-29 단계11 보완 - SNS 8채널 Gemini Prompt를 V1·Beta 기준으로 재구현

## 조사 결과 요약 (포크로 병렬 조사, 실제 검색 기반)

- **V1의 실제 시스템 프롬프트 원문은 확보하지 못했다.** V1은 이 PC의 로컬 파일이 아니라
  `http://127.0.0.1:8011/api/generate-prompt`라는 별도 실행 중인(Docker로 추정) 서비스를
  호출하는 구조였고, `F:\StoryMaker_V1` 폴더에는 Supertonic TTS 백업만 있을 뿐 실제 웹앱
  소스가 없었다. 전체 드라이브 재귀 검색도 시간 초과로 V1 원본은 찾지 못했다.
- Beta(`F:\StoryMaker_beta\app\beta_gemini.py`)도 자체 프롬프트를 만들지 않고 V1의 8011
  API를 그대로 호출한 뒤, "Beta 8채널 저장 어댑터"라는 짧은 텍스트만 덧붙인다. 이번에
  실제로 확보한 원문은 이 어댑터 텍스트뿐이며, 여기서 다음을 확인했다:
  - 서사 구조: "고객 불편 → 현장 확인 → 원인 진단 → 작업 과정 → 작업 후 확인"을 본문의
    중심으로 삼으라는 명시적 지시
  - 날씨·시간대는 도입부의 짧은 생활 배경으로만 쓰고 본문 중심으로 확장하지 말라는 절제 규칙
  - 채널별 정량 글자수: 블로그 약 2000자, 플레이스/구글 250~450자, 당근 500~800자
  - `tones` 기본값이 `["전문가","친근함","신뢰감","현장감","차분함","진지함"]`으로, 이미
    이전 커밋에서 StoryMaker_C에 반영한 업체 감성 톤 태그와 정확히 일치함(교차 검증됨)
  - Beta의 실제 8채널 코드(BLOG/NAVER_PLACE/GOOGLE_BUSINESS/INSTAGRAM/CARROT/CAROUSEL_7/
    PODCAST_50/PODCAST_80)는 StoryMaker_C의 8채널(네이버블로그/인스타그램/페이스북/
    당근마켓/네이버플레이스/구글비즈니스/카카오채널/숏폼원고)과 이름이 다르다. 사용자
    지시서의 "실제 채널명이 다르면 현재 시스템 값을 기준으로 한다"에 따라 StoryMaker_C의
    기존 8채널 정의를 그대로 쓰고, Beta에서 확인된 규칙(서사구조·날씨절제·정량 글자수
    원칙)만 이식했다.
- V1 원문을 확보하지 못한 만큼, 정량 글자수 값은 Beta에서 확인된 값을 그대로 쓴 채널
  (블로그·플레이스·구글·당근)과, 사용자 지시서 4장의 채널별 설명을 근거로 새로 정한
  채널(인스타·페이스북·카카오·숏폼)이 섞여 있다. "V1과 100% 동일"이라고 단정하지 않고
  이 사실을 그대로 기록한다.

## 구현 (`app/ai/prompt_builder.py`)

- 시스템 규칙에 공통 서사 구조(5단계)와 날씨·시간대 절제 규칙 추가.
- `_CHANNEL_WRITING_RULES` 딕셔너리로 8개 채널 각각의 정량 글자수와 문체 규칙을 정의하고,
  `_channel_slot_schema()`의 `body` 필드 설명에 그대로 주입해 프롬프트에 반영:
  - 네이버 블로그 1500~2000자, 소제목 2~4개, 서사구조 강조
  - 인스타그램 250~450자, 시선 끄는 첫 문장
  - 페이스북 400~700자, 설명형·지역성·신뢰감
  - 당근마켓 300~600자, 생활밀착형 어조, 과장 자제
  - 네이버 플레이스/구글 비즈니스 150~350자, 방문·문의 유도, 블로그형 금지
  - 카카오채널 150~300자, 간결한 안내+상담 유도
  - 숏폼 원고: TTS 적합 구어체, 장면 전환 문장 단위, 3초 후킹, 문제→과정→해결→CTA
- 기존 안전장치(프롬프트 인젝션 방어, 업체 정보=데이터 취급, 빈 필드 금지, 가짜 정보
  생성 금지, 채널 간 복사 금지)는 전혀 건드리지 않았다 — 이번 요청 3장의 "Prompt 안전성"
  요구사항이 이미 전부 충족돼 있던 부분이라 유지만 했다.
- 현재 파서(엄격한 JSON 단일 응답)를 그대로 유지했다 — 지시서 3장에 "현재 파서가
  안정적으로 처리할 수 있도록 정확한 JSON... 기존 검증된 포맷을 사용" 명시가 있어,
  Beta처럼 JSON 실패 시 텍스트 블록으로 폴백하는 이중 파서는 추가하지 않았다(범위 밖으로
  명확히 판단).
