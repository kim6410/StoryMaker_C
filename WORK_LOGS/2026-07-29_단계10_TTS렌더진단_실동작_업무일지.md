## 2. 완성한 화면과 URL

`/admin/diagnostics` (관리자 메뉴 "TTS·렌더 진단", 작업관리와 저장공간·감사로그 사이)

실제 동작하는 항목:

- **FFmpeg·FFprobe 상태**: 페이지를 열 때마다 `subprocess.run([exe, "-version"])`를
  실제 실행해 버전 문자열과 종료코드를 그대로 보여준다("다시 검사" 버튼 = 새로고침으로
  다시 실행).
- **Range 응답 검사**: 버튼을 누르면 브라우저가 실제 완성된 MP4의 스트리밍 URL에
  `Range: bytes=0-1023` 헤더로 `fetch()`를 보내고, 실제 `206 Partial Content` 응답과
  `Content-Range` 헤더 유무를 확인해 결과를 카드에 반영한다(완성 영상이 없으면 버튼
  비활성화 + 이유 표시).
- **TTS 성공/실패 집계, 음성별 문장 통계**: `content_tts_sentences` 실집계.
- **평균 생성시간(추정)**: 별도 계측 컬럼이 없어 문장 완료 시각 간 실제 간격을 SQL
  윈도우 함수로 구한 추정값이며, 화면에 "추정"으로 명시한다.
- **최근 TTS 실패 + 재시도 링크**: 실패한 문장을 최근 순으로 보여주고, 클릭하면 기존
  `/content/job/{uid}/tts`(단계7에서 이미 검증된 문장별 재생성 화면)로 이동한다. 새
  재시도 엔진은 만들지 않았다.
- **렌더 방식별 성공률**: `content_mp4`를 `render_method`·`status`로 집계.
- **서버 폴백 이유 집계**, **브라우저 WebGPU/WebCodecs 지원 비율**: 각각
  `content_mp4.fallback_reason`, `content_render_diagnostics` 실집계.
- **최근 MP4 메타데이터** 표.
