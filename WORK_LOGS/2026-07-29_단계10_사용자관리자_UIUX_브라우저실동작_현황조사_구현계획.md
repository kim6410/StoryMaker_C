## 4. 이번 회차 구현 범위와 이연 결정

자동 선택 우선순위(00_READ_FIRST 661~669행: 1.기존정상기능보존 2.데이터보존 3.이해하기
쉬운흐름 4.최소수정·회귀위험최소화 5.접근성 6.복구가능성 7.명확성>화려함)에 따라 결정한다.

**이번 회차에 구현:**
1. 관리자 대시보드(`/admin`) - 실 DB 집계 + 드릴다운
2. 회원관리 고도화(`/admin/members`, `/admin/members/{id}`) - 검색/필터/상세/활성전환/메모/사용량조정/플랜변경
3. 작업관리(`/admin/jobs`) - 전체 작업 목록/검색/필터, 상세는 기존 `/content/job/{uid}` 페이지
   재사용(이미 `_get_owned_project_or_none`에 관리자 우회 로직이 있어 신규 코드 없이도
   관리자가 모든 작업을 열람할 수 있음을 확인했다). 재시도는 이미 존재하는 채널별/문장별
   재생성 엔드포인트를 그대로 재사용한다(신규 재시도 엔진을 따로 만들지 않음 - 최소 수정).
4. 저장공간·감사로그(`/admin/storage`) - 실 디스크 사용량 + audit_logs 검색

**이연(사유 명시, 다음 세션 우선순위 권장):**
1. **Provider·프롬프트 관리 화면 전체**(지시서 22장) - Provider 상태·테스트 호출,
   프롬프트 버전관리/편집/복원 기능은 관련 DB 테이블(prompts, prompt_versions 등)이
   전혀 존재하지 않아 스키마 설계부터 새로 시작해야 하는 독립적인 신규 서브시스템이다.
   API 키를 다루는 화면이라 리스크도 높다. "최소 수정과 회귀 위험 최소화" 원칙에 따라
   이번 회차에는 손대지 않는다.
2. **TTS·렌더 심층 진단 전용 화면**(지시서 23장 전체) - 음성별 통계, 브라우저 기능탐지
   심층 대시보드는 별도 화면으로 만들지 않고, 저장공간 화면과 `content_render_diagnostics`
   원시 데이터 열람으로 최소 대체한다. 전용 UI는 다음 세션으로 이연한다.
3. **썸네일 8종 선택 기능**(지시서 15장, 9~11번 항목) - 실제 이미지 생성 백엔드가 전혀
   없는 신규 기능이며, 단계10A와 동일한 사유로 이번 회차에도 이연한다.
4. **1920×1080/1366×768/768×1024/360×800 전 해상도 스크린샷 실측과 Tab 순서 실측** -
   시간 제약상 이번 회차에는 핵심 해상도(모바일 390px, 태블릿 1024px, 데스크톱 1920px)
   위주로 실측하고 나머지는 코드 감사로 대체한다(레이아웃이 max-width 카드형이라 회귀
   위험은 낮다고 판단).
