# StoryMaker_C 단계 11 완료 화면 UI·UX 분석 및 V1·Beta 비교 상세 개선 최종 작업지시서

작성일: 2026-07-29

작업 루트: `F:\StoryMaker_C`

## 1. 작업 목적

현재 StoryMaker_C는 핵심 기능이 상당 부분 실제 동작하는 단계에 도달했다.

특히 다음 기능은 이미 구현 또는 검증이 끝난 상태다.

- 신규 업체 등록
- 다중 업체 등록
- 업체 수정
- 기본 업체 전환
- 업체 활성·비활성
- 대표 이미지 업로드
- 콘텐츠용 사진·영상 복수 업로드
- 타 사용자 GET·POST 접근 차단
- 실HTTP E2E 28/28 PASS 2회
- DB 셀프테스트 24/24 PASS 2회
- POST 권한 실패 303 처리
- 사용자 대시보드 실데이터 표시
- 관리자 대시보드 실 DB 집계
- 사용자·관리자 브랜드 명칭 정리
- SVG 메뉴 아이콘 적용
- 구독 화면 실데이터 연결

이번 작업은 위 기능을 다시 구현하는 작업이 아니다.

이미 완료된 화면을 실제 SaaS 서비스 수준으로 정리하고, V1과 Beta에서 사용자가 익숙하게 느꼈던 흐름을 StoryMaker_C 구조에 맞게 새로 설계하는 작업이다.

최종 사용자 반응은 다음이어야 한다.

> 새 프로그램 같지 않고, 익숙한데 훨씬 좋아졌다.

기능은 많아졌지만 사용자는 더 쉽게 느껴야 한다.

관리자는 정보가 많아졌지만 운영 판단은 더 빨라져야 한다.

## 3. 현재 완료 화면 분석

### 3.1 공통 레이아웃과 사이드바

현재 구현된 장점:

- 사용자 화면은 `StoryMaker`
- 관리자 화면은 `StoryMaker 관리자 센터`
- 사용자 메뉴와 관리자 메뉴 그룹 존재
- 메뉴별 SVG 아이콘 적용
- 서버 `active` 값 기반 활성 메뉴
- 모바일 햄버거
- 오버레이
- 상단 사용자 이메일
- 로그아웃 버튼
- 공통 토스트 영역

현재 문제:

- 사용자 메뉴와 관리자 메뉴가 한 사이드바에 이어져 있어 관리자 진입 후에도 사용자 화면처럼 느껴질 수 있다.
- 관리자 업무에 필요한 메뉴 우선순위가 약하다.
- 메뉴 그룹 구분선과 관리자 센터 전환 인지가 부족하다.
- hover·active·focus 상태가 시각적으로 비슷해질 위험이 있다.
- 모바일 메뉴에서 현재 위치 인식이 약할 수 있다.
- 직접 URL 접근, 새로고침, 뒤로가기 시 활성 메뉴가 항상 일치하는지 검증되지 않았다.

개선 지시:

1. 현재 SVG 아이콘 스타일은 유지한다.
2. 사용자 메뉴와 관리자 메뉴의 시각적 그룹을 분명히 한다.
3. 관리자 화면에서는 관리자 그룹을 먼저 노출하는 방안을 검토한다.
4. 사용자 메뉴로 돌아가는 기능은 `사용자 화면으로 돌아가기`처럼 한 개의 명확한 진입점으로 정리한다.
5. 활성 메뉴는 배경색, 좌측 강조선, 아이콘 색상, 텍스트 굵기 중 최소 3개 요소로 구분한다.
6. hover는 활성 메뉴보다 약하게 표현한다.
7. keyboard focus는 outline을 제거하지 말고 명확히 표시한다.
8. 모바일에서 메뉴 선택 후 사이드바가 자동으로 닫히는지 확인한다.
9. 브라우저 뒤로가기 후 메뉴 활성 상태와 페이지 제목을 동기화한다.
10. 관리자 전용 CSS는 사용자 화면을 오염시키지 않도록 별도 namespace를 사용한다.

PASS 기준:

- 같은 시점에 활성 메뉴는 정확히 1개만 강하게 보인다.
- hover와 active를 혼동하지 않는다.
- 360px 화면에서 메뉴 텍스트가 잘리지 않는다.
- 관리자 화면에서 현재 관리자 센터에 있다는 사실이 즉시 인식된다.

### 3.2 사용자 대시보드

현재 구현된 요소:

- 사용자 인사말
- 현재 업체명
- 업체 정보 수정 링크
- 업체 미등록 안내
- 이번 달 제작량
- 진행 중·실패·완료 통계
- 새 콘텐츠 제작 CTA
- 보관함 바로가기
- 최근 MP4 1개
- 최근 작업 표

현재 장점:

- 실데이터 기반이다.
- 실패·진행·완료 상태를 구분한다.
- 첫 사용자에게 업체 등록 순서를 안내한다.
- 최근 작업에서 결과 보기·재시도·이어하기가 가능하다.

현재 문제:

- 통계 카드와 표가 먼저 보여 첫 화면이 운영 화면처럼 느껴진다.
- 현재 업체의 대표 이미지와 브랜드 정보가 살아나지 않는다.
- 최근 MP4 영역은 작은 영상 하나만 보이고 오른쪽 공간이 비어 있다.
- 다중 업체 사용자가 대시보드에서 업체를 전환할 수 없다.
- 최근 썸네일, SNS 결과, 업로드 이미지·영상이 보이지 않는다.
- 사용자의 다음 행동보다 숫자가 먼저 강조된다.
- V1·Beta의 제작 중심 경험이 대시보드 첫 화면에 연결되지 않는다.

V1에서 참고할 요소:

- 업체 정보와 제작 진입의 가까운 연결
- 마이페이지·업체정보·제작 화면 간 짧은 동선
- 사용량과 현재 업체를 동시에 파악하는 구조

Beta에서 참고할 요소:

- 딸깍 제작으로 바로 들어가는 강한 CTA
- 최근 결과물 중심 화면
- MP4·썸네일·SNS 슬롯이 시각적으로 살아 있는 구성
- 작업 완료 후 다음 행동이 명확한 구조

개선 지시:

#### A. Hero 영역 신설

대시보드 최상단을 단순 인사말이 아닌 Hero 영역으로 재구성한다.

Hero에는 다음을 포함한다.

- 현재 기본 업체 대표 이미지
- 업체명
- 업종
- 지역
- 한 줄 소개
- 현재 플랜
- 이번 달 사용량
- 남은 제작 횟수
- 사진 수
- 영상 수
- `새 콘텐츠 제작`
- `최근 작업 이어하기`
- `업체 전환`
- `업체 정보 수정`

Hero는 슬라이드 구조를 적용한다.

권장 슬라이드:

1. 현재 업체 소개
2. 최근 완성 MP4
3. 최근 선택 썸네일
4. 최근 SNS 8채널 결과 요약
5. 최근 업데이트 또는 실제 공지

자동 재생 조건:

- 5~7초 간격
- 마우스 hover 시 정지
- 키보드 포커스 시 정지
- 좌우 버튼 제공
- 현재 슬라이드 위치 표시
- `prefers-reduced-motion`에서 자동 재생 비활성
- 슬라이드 데이터가 1개이면 캐러셀 UI를 억지로 표시하지 않음

가짜 공지나 SAMPLE 데이터는 사용하지 않는다.

실데이터가 없으면 해당 슬라이드는 제외한다.

#### B. 통계 카드 재구성

현재 4개 숫자 카드를 유지하되 행동 중심으로 재정렬한다.

우선순위:

1. 남은 제작량
2. 진행 중 작업
3. 실패 작업
4. 이번 달 완성

각 카드는 클릭 가능해야 한다.

카드 하단에는 다음 행동을 한 줄로 표시한다.

예:

- 남은 17회 · 새 콘텐츠 만들기
- 진행 1건 · 이어서 작업
- 실패 2건 · 원인 확인
- 완성 8건 · 보관함 보기

#### C. 최근 콘텐츠 영역

최근 MP4를 단독 작은 video로 두지 않는다.

가로형 콘텐츠 카드로 재구성한다.

포함 정보:

- 대표 썸네일
- 영상 재생
- 제목
- 업체명
- 생성일
- 작업 상태
- 사용한 이미지 수
- 사용한 영상 수
- SNS 결과 보기
- MP4 다운로드
- 보관함 열기
- 동일 업체로 새 제작

오른쪽 빈 공간이 생기지 않도록 2열 구조를 사용한다.

#### D. 첫 사용자 빈 상태

업체가 없을 때 단순 안내문이 아니라 온보딩 단계를 표시한다.

1. 업체 등록
2. 대표 이미지 등록
3. 사진·영상 업로드
4. 콘텐츠 주제 입력
5. SNS 8채널 생성
6. TTS·SRT·MP4 생성
7. 썸네일 선택
8. 보관함 저장

현재 단계는 강조하고 완료 단계는 체크한다.

첫 CTA는 `첫 업체 등록하기`로 한다.

PASS 기준:

- 로그인 직후 사용자가 3초 안에 다음 행동을 찾을 수 있다.
- 현재 업체와 남은 제작량이 첫 화면에서 보인다.
- 최근 MP4·썸네일·SNS 중 실제 존재하는 결과가 Hero 또는 최근 콘텐츠 카드에 나타난다.
- 데이터가 없을 때 빈 박스가 아닌 다음 행동이 보인다.

### 3.3 마이페이지

현재 구현된 요소:

- 업체 탭
- 계정 탭
- 현재 기본 업체 카드
- 대표 이미지
- 업체명·업종·지역
- 업체관리 이동
- 비밀번호 변경

현재 장점:

- 업체 수정 기능을 마이페이지에서 분리해 책임이 명확하다.
- 현재 기본 업체를 확인할 수 있다.
- 비밀번호 변경이 실제 계정에 영향을 준다는 설명이 있다.

현재 문제:

- 업체 탭 내용이 카드 하나뿐이라 탭 구조가 과하다.
- 여러 업체가 있어도 현재 기본 업체 외에는 알 수 없다.
- 업체관리 CTA가 약하다.
- 계정 탭에 가입일·플랜·사용량·저장공간·이메일 등의 기본 계정 정보가 없다.
- 저장 성공 메시지가 어떤 작업의 결과인지 불명확하다.
- 비밀번호 변경 후 세션 영향이 더 구체적으로 보여야 한다.

V1에서 참고할 요소:

- 업체정보 필드의 풍부함
- 사용자 프로필·업체·구독 정보를 한 화면에서 연결하는 방식
- 제작으로 바로 이동하는 동선

Beta에서 참고할 요소:

- 제작용 이미지·영상 준비상태 표시
- 기본 업체가 딸깍 제작에 어떻게 쓰이는지 설명하는 방식

개선 지시:

1. 상단에 계정 요약 카드를 추가한다.
2. 표시 항목은 이메일, 표시명, 가입일, 플랜, 이번 달 사용량, 남은 제작량, 저장공간으로 한다.
3. 업체 탭에는 기본 업체 외에 `전체 업체 N개`, `활성 N개`, `비활성 N개`를 표시한다.
4. 다른 업체 2~3개를 축약 카드로 보여주고 `전체 업체 관리`로 연결한다.
5. 기본 업체 카드에 `이 업체로 콘텐츠 만들기` 버튼을 추가한다.
6. 대표 이미지가 없으면 `대표 이미지 등록` CTA를 표시한다.
7. 사진·영상 수를 표시한다.
8. `업체 관리로 이동`을 기본 CTA로 강화한다.
9. 비밀번호 변경에는 현재 비밀번호, 새 비밀번호, 새 비밀번호 확인을 사용한다.
10. 변경 성공 후 모든 세션 무효화 여부를 실제 동작과 일치하게 표시한다.
11. 저장 성공은 toast와 inline 상태를 함께 사용하되 중복 노출은 피한다.

PASS 기준:

- 마이페이지에서 계정 상태와 기본 업체 준비상태를 동시에 파악한다.
- 업체관리와 새 콘텐츠 제작으로 각각 1회 클릭 이내 이동한다.
- 다중 업체 사용자도 다른 업체가 있다는 사실을 바로 알 수 있다.

### 3.4 업체관리 목록

현재 구현된 요소:

- 업체 카드
- 대표 이미지
- 기본 업체 배지
- 비활성 배지
- 업종·지역
- 상세·수정
- 기본 업체 선택
- 활성·비활성
- 새 업체 등록

현재 장점:

- 핵심 다중 업체 기능이 실제 동작한다.
- 카드 안에서 주요 상태를 확인한다.
- 소유권과 POST 접근 차단이 검증되어 있다.

현재 문제:

- 업체가 많아질수록 검색과 필터가 필요하다.
- 비활성 업체 전체 opacity가 낮아 가독성이 떨어질 수 있다.
- 기본 업체 전환의 영향 설명이 없다.
- 비활성화 영향 설명이 없다.
- 미디어 수·최근 수정일·최근 제작일이 없다.
- 카드에서 새 콘텐츠 제작으로 바로 이동할 수 없다.
- 대표 이미지가 없는 카드의 개선 행동이 없다.

V1에서 참고할 요소:

- 풍부한 업체 정보 필드
- 업체정보 수정 후 제작 화면으로 이어지는 동선

Beta에서 참고할 요소:

- 제작에 사용할 이미지·영상 준비상태
- 선택된 업체가 제작 흐름에 명확히 반영되는 방식

개선 지시:

1. 상단 검색을 추가한다.
2. 검색 대상은 업체명, 업종, 지역이다.
3. 활성·비활성·기본 업체 필터를 추가한다.
4. 정렬은 최근 수정, 업체명, 최근 제작 순으로 제공한다.
5. 카드에 사진 수, 영상 수, 최근 수정일, 최근 제작일을 표시한다.
6. 카드에 `콘텐츠 만들기` 버튼을 추가한다.
7. 대표 이미지가 없으면 `대표 이미지 등록` 버튼을 표시한다.
8. 기본 업체 변경 전 확인 모달을 표시한다.
9. 확인 문구는 `앞으로 새 콘텐츠 제작 화면의 기본 선택 업체가 변경됩니다.`로 한다.
10. 비활성화 전 확인 모달을 표시한다.
11. 기존 콘텐츠와 보관함은 유지되고 신규 제작 기본 선택에서 제외되는지 실제 동작에 맞게 설명한다.
12. 비활성 카드는 opacity 대신 배경·배지·테두리로 구분한다.
13. 기본 업체는 비활성화할 수 없거나, 비활성화 전에 다른 기본 업체를 선택하도록 한다.
14. 업체 수가 1개일 때 불필요한 필터 UI는 최소화한다.

PASS 기준:

- 업체가 20개여도 검색과 필터로 빠르게 찾는다.
- 기본 업체 변경과 비활성화의 영향을 사용자가 이해한다.
- 업체 카드에서 수정·미디어관리·콘텐츠제작이 명확히 구분된다.

### 3.5 업체 상세·수정 화면

현재 기능은 완료되었으므로 API와 ownership 구조를 바꾸지 않는다.

개선 지시:

1. 화면 상단에 업체명, 기본 여부, 활성 여부, 대표 이미지 준비상태를 요약한다.
2. 폼을 다음 섹션으로 구분한다.
   - 기본 정보
   - 지역·업종
   - 주요 서비스
   - 홍보 문구와 요청사항
   - 대표 이미지
   - 콘텐츠용 사진
   - 콘텐츠용 영상
3. 필수 입력과 선택 입력을 구분한다.
4. 저장 버튼은 화면 하단에만 두지 말고 긴 폼에서는 sticky action bar를 검토한다.
5. 저장 전 변경 여부를 감지한다.
6. 미저장 상태에서 이동하면 경고한다.
7. 대표 이미지 업로드 직후 미리보기를 갱신한다.
8. 미디어 업로드 중 개별 진행 상태를 표시한다.
9. 파일별 업로드 실패를 전체 실패로 처리하지 않고 개별 표시한다.
10. 이미지와 영상을 시각적으로 구분한다.
11. 원본 파일명, 파일 크기, 업로드일을 표시한다.
12. 삭제 기능이 있다면 확인 절차와 소유권 검사를 유지한다.
13. `이 업체로 콘텐츠 만들기` 버튼을 상단에 제공한다.

PASS 기준:

- 처음 등록하는 사용자도 어떤 항목을 입력해야 하는지 이해한다.
- 이미지·영상 업로드 상태를 개별적으로 확인한다.
- 저장하지 않은 변경을 실수로 잃지 않는다.

### 3.6 새 콘텐츠 제작 화면

현재 구현된 요소:

- 5단계 표시
- 업체 선택
- 업체 정보 읽기 전용 표시
- 주제
- 키워드
- 말투
- 길이
- 음성
- 배경음악
- 음악 미리듣기
- 사진·영상 복수 선택
- 중복 클릭 방지

현재 장점:

- 업체 정보와 제작 조건이 분리되어 있다.
- 실제 업체 미디어를 선택한다.
- 업체가 없을 때 등록 화면으로 연결한다.
- 제작 단계가 상단에 존재한다.

현재 문제:

- 정적 단계 표시라 진행감이 약하다.
- 한 화면에 폼이 길게 이어진다.
- 필수와 선택의 위계가 약하다.
- 미디어 선택 개수와 선택 상태가 약하다.
- MP4에 이미지가 아직 직접 반영되지 않는 한계를 작은 문구로만 안내한다.
- 제작 전 준비상태 요약이 없다.
- V1·Beta 딸깍 제작의 핵심인 자동 진행, 포커스 이동, 결과 슬롯, 완료 후 다음 단계 연결이 약하다.

Beta에서 반드시 계승할 UX:

- 콘텐츠 자동생성 중심 CTA
- 현재 단계 강조
- 완료 단계 체크
- 단계별 진행 애니메이션
- 다음 단계 자동 포커스
- SNS 8채널 결과 슬롯
- TTS·SRT 생성 상태
- MP4 렌더 진행
- MP4 완료 후 썸네일 선택
- 8개 미리보기 중 1개 저장
- 보관함 자동 연결

개선 지시:

#### A. 입력 화면 구조

입력 화면을 다음 순서로 재구성한다.

1. 업체 선택
2. 주제와 키워드
3. 말투와 길이
4. 음성·배경음악
5. 사진·영상 선택
6. 제작 준비 요약
7. 콘텐츠 자동생성 시작

업체 정보의 모든 disabled input을 그대로 길게 보여주지 않는다.

업체 정보는 요약 카드로 표시한다.

필요 시 `업체 정보 펼쳐보기`로 상세를 본다.

#### B. 미디어 선택 UX

- 이미지·영상 탭 또는 필터
- 선택 개수 표시
- 전체 선택
- 선택 해제
- 선택된 카드 강조
- 영상에는 재생 아이콘
- 대표 이미지는 별도 표시
- 미디어가 없으면 업로드 CTA
- 업로드 후 현재 제작 화면으로 돌아올 수 있는 return URL 유지

#### C. 제작 준비 요약

제작 시작 직전에 다음을 표시한다.

- 선택 업체
- 주제
- 키워드
- 말투
- 길이
- 음성
- 음악
- 이미지 N개
- 영상 N개
- 남은 제작량

필수 조건이 부족하면 제작 버튼을 비활성화하고 이유를 표시한다.

#### D. 버튼 명칭

`제작 시작`보다 기존 Beta와 익숙한 `콘텐츠 자동생성`을 우선 검토한다.

단, 실제 동작과 일치해야 한다.

버튼 아래에 다음 진행을 간단히 표시한다.

`SNS 8채널 → TTS·SRT → MP4 → 썸네일 → 보관함`

#### E. 진행 화면

작업 시작 후 한 화면에서 다음 상태를 순차적으로 보여준다.

1. 원고 생성
2. SNS 8채널
3. 음성 생성
4. 자막 생성
5. MP4 렌더
6. 썸네일 생성
7. 보관함 저장

각 단계는 다음 상태를 가진다.

- 대기
- 진행
- 완료
- 실패
- 재시도 가능

현재 단계 아래에 실제 메시지를 표시한다.

예:

- 업체 정보를 분석하고 있습니다.
- SNS 8채널 원고를 정리하고 있습니다.
- 음성을 생성하고 있습니다.
- 자막 시간을 맞추고 있습니다.
- MP4를 렌더링하고 있습니다.

가짜 퍼센트는 사용하지 않는다.

실제 진행률이 없으면 단계형 상태만 표시한다.

#### F. 완료 후 이동

- SNS 8채널 완료 시 결과 슬롯으로 자동 스크롤
- MP4 완료 시 영상 미리보기로 자동 스크롤
- MP4 완료 후 썸네일 선택 영역 활성화
- 썸네일 선택 완료 후 보관함 이동 CTA 강조

PASS 기준:

- 초보 사용자가 한 화면에서 현재 단계와 다음 단계를 이해한다.
- 중복 클릭으로 작업이 2개 생성되지 않는다.
- 새로고침 후 현재 작업 상태를 복구한다.
- 실패 시 원인과 재시도 가능 단계를 표시한다.
- 완료 후 사용자가 다음 행동을 찾기 위해 화면을 탐색하지 않는다.

### 3.7 보관함

현재 템플릿을 조사한 뒤 V1·Beta와 비교한다.

V1에서 참고할 요소:

- 결과물 종류 확인
- 제목·업체·생성일 정보
- 다운로드 동선

Beta에서 참고할 요소:

- 대표 썸네일 중심 카드
- MP4, SNS 8채널, MP3, SRT, 원본 이미지·영상의 통합 결과
- 선택한 대표 썸네일 1개 표시
- 채널별 복사
- 통합 다운로드

개선 지시:

1. 표 중심이면 썸네일 카드 중심으로 재구성한다.
2. 카드에 대표 썸네일, 제목, 업체, 생성일, 상태를 표시한다.
3. MP4 재생 버튼을 제공한다.
4. SNS 8채널 결과 존재 여부를 표시한다.
5. MP3·SRT·썸네일·원본 미디어 존재 여부를 아이콘이나 배지로 표시한다.
6. `상세 보기`, `다운로드`, `다시 제작`, `삭제 또는 보관 정책`을 분리한다.
7. 검색은 제목·업체명으로 한다.
8. 업체별 필터를 제공한다.
9. 생성일 정렬을 제공한다.
10. 빈 상태는 새 콘텐츠 제작으로 연결한다.
11. 파일 누락 시 완료처럼 보이지 않도록 `일부 결과 누락` 상태를 표시한다.
12. 다른 사용자 파일 URL 추측 접근 차단을 유지한다.

PASS 기준:

- 보관함 첫 화면에서 결과물의 성격을 썸네일로 인식한다.
- 3회 이내 클릭으로 MP4 재생 또는 SNS 결과 복사가 가능하다.
- 파일 누락과 완전 완료를 구분한다.

### 3.8 관리자 대시보드

현재 구현된 요소:

- 회원 통계
- 가입 통계
- 작업 통계
- AI 호출
- TTS 성공
- MP4 렌더 통계
- 폴백
- 저장공간
- Gemini 설정 상태
- 최근 실패 작업

현재 장점:

- 실 DB 집계다.
- 카드가 상세 화면으로 연결된다.
- 최근 실패 작업을 확인한다.

현재 문제:

- 숫자 카드가 과도하게 많다.
- 정상 정보와 조치 필요 정보가 같은 위계다.
- 관리자 운영 우선순위가 약하다.
- 업체관리, Provider, Prompt, 요청사항이 핵심 운영 동선에 포함되지 않았다.
- 단일 Gemini 상태가 다중 Provider 구조와 맞지 않는다.
- 장기 진행 작업, 미처리 요청, 저장공간 경고, Provider 실패가 없다.

V1에서 참고할 요소:

- 회원 상세에서 구독·사용량·업체를 연결하는 방식
- 관리자 메뉴별 실운영 도구

Beta에서 참고할 요소:

- 작업 진행 상태를 즉시 파악하는 방식
- 실패·재시도·결과 상태 구분

개선 지시:

#### A. 대시보드 정보 위계

대시보드를 다음 4영역으로 재구성한다.

1. 즉시 조치 필요
2. 오늘의 운영 현황
3. 회원·업체 현황
4. 시스템·Provider 상태

#### B. 즉시 조치 필요

실데이터가 있는 항목만 표시한다.

- 실패 작업
- 장시간 진행 작업
- 미처리 요청사항
- Provider 오류
- 저장공간 경고
- 파일 누락 작업
- 구독 또는 크레딧 이상

0건이면 조용한 정상 상태로 표시한다.

#### C. 핵심 카드 축소

상단 핵심 카드는 4~6개로 제한한다.

권장:

- 전체 회원
- 활성 업체
- 오늘 작업
- 실패 작업
- 미처리 요청
- 저장공간

나머지 숫자는 하위 섹션으로 이동한다.

#### D. 운영 바로가기

다음 바로가기를 배치한다.

- 회원 검색
- 업체 검색
- 작업 조회
- 과금관리
- Provider 관리
- Prompt 관리
- 저장공간
- 감사로그

#### E. Provider 상태

단일 Gemini 설정 여부 대신 Provider별 상태를 표시한다.

- 활성 여부
- 우선순위
- 최근 성공
- 최근 실패
- 오류 메시지

API 키 원문은 표시하지 않는다.

PASS 기준:

- 관리자가 로그인 후 5초 안에 조치할 문제를 찾는다.
- 정상 통계와 장애 통계의 시각적 위계가 분명하다.
- 회원→업체→작업→과금으로 자연스럽게 이동한다.

---

### 3.9 관리자 회원관리

개선 지시:

- 아이디·이메일·업체명 검색
- Free·Starter·관리자 필터
- 업체 등록 여부 필터
- 가입일·최근 로그인 정렬
- 현재 플랜
- 잔여량
- 업체 수
- 대표 업체
- 최근 작업
- 저장공간
- 상세 드릴다운

회원 상세에서는 다음을 탭 또는 섹션으로 구분한다.

1. 계정
2. 업체
3. 구독·크레딧
4. 작업
5. 보관함
6. 요청사항
7. 감사로그

사용자 화면과 같은 카드·배지 시스템을 쓰되 관리자 전용 위험 작업은 별도 색상과 확인 절차를 사용한다.

---

### 3.10 관리자 업체관리

개선 지시:

- 전체 업체 검색
- 회원 검색
- 업종·지역 필터
- 활성·비활성
- 기본 업체 여부
- 대표 이미지 여부
- 사진 수
- 영상 수
- 최근 수정일
- 최근 제작일

업체 상세에서 소유 회원으로 이동할 수 있어야 한다.

회원 상세에서 업체 목록으로 이동할 수 있어야 한다.

관리자 수정 기능을 제공할 경우 서버 측 관리자 권한과 소유권 경계를 명확히 유지한다.

감사로그가 없다면 무단으로 DB 컬럼을 추가하지 말고 설계안을 먼저 작성한다.

### 3.11 Provider·Prompt 관리자 화면

현재 스키마만 완료된 상태라면 UI를 mock으로 채우지 않는다.

Provider 관리:

- 목록
- 이름
- 코드
- 활성 여부
- 우선순위
- 모델명
- 키 설정 여부
- 최근 성공·실패
- 평균 응답시간
- 연결 테스트

Prompt 관리:

- 목록
- 용도
- 채널
- 버전
- 활성 여부
- 기본 여부
- Provider
- 수정일
- 상세 편집
- 변수 검증
- 테스트 실행
- 변경 이력

API 키는 원문이나 길이를 유추할 수 있는 형태로 반환하지 않는다.

Prompt 테스트는 운영 작업과 구분한다.

## 5. 공통 UI·UX 완료 기준

모든 화면에 다음 상태를 구현한다.

- 로딩
- 빈 결과
- 검색 결과 없음
- 권한 없음
- API 오류
- 저장 중
- 저장 성공
- 저장 실패
- 재시도
- 중복 클릭 방지
- 미저장 변경 경고

색상만으로 상태를 표현하지 않는다.

아이콘, 텍스트, 배지, 테두리를 함께 사용한다.

모든 버튼은 다음을 구분한다.

- 기본 행동
- 보조 행동
- 위험 행동
- 비활성 행동

폼 오류는 필드 가까이에 표시한다.

서버 오류 원문을 그대로 노출하지 않는다.

## 8. Claude Code에 전달할 실행 문장

아래 지시를 그대로 수행한다.

> 현재 완료된 기능을 다시 구현하지 말고, 먼저 StoryMaker_C의 사용자 대시보드, 마이페이지, 업체관리, 업체 상세, 새 콘텐츠 제작, 보관함, 관리자 대시보드, 회원관리, 업체관리 화면을 실제 코드 기준으로 전수 조사하라.
>
> V1과 Beta는 읽기 전용으로 열어 화면 목적, 정보 구조, 사용자 동선, 딸깍 제작 단계, 보관함 결과 표현만 비교하라. 코드·DB·CSS·JS·정적파일은 복사하지 마라.
>
> 조사 결과를 `현재 구현`, `V1 장점`, `Beta 장점`, `StoryMaker_C에 적용할 항목`, `가져오면 안 되는 지뢰`, `수정 파일`, `검증 기준` 형식으로 먼저 보고하라.
>
> 그다음 현재 진행 중인 기능 단위를 자연스럽게 완료한 뒤, 중복되지 않는 UI·UX 보완만 단계별로 적용하라.
>
> 사용자 대시보드는 현재 기본 업체, 대표 이미지, 남은 제작량, 최근 MP4, 최근 썸네일, SNS 결과를 보여주는 Hero 슬라이드 중심으로 재구성하라.
>
> 새 콘텐츠 제작은 Beta 딸깍 제작의 단계형 진행, SNS 8채널, TTS·SRT, MP4, 썸네일 선택, 보관함 저장 흐름을 StoryMaker_C의 repository, migration, ownership, upload 구조에 맞게 새로 구현하라.
>
> 관리자 대시보드는 숫자 카드 나열을 줄이고 즉시 조치 필요, 오늘의 운영, 회원·업체, 시스템·Provider 순으로 재구성하라.
>
> 업체관리와 마이페이지는 실제 다중 업체 기능이 화면에서 자연스럽게 연결되도록 하고, 업체 카드에서 수정·미디어관리·콘텐츠제작으로 바로 이동할 수 있게 하라.
>
> 모든 화면은 로딩, 빈 상태, 오류, 저장, 재시도, 중복 클릭 방지, 모바일, keyboard focus를 포함해야 한다.
>
> 8032는 사용자가 직접 검증 중이므로 임의 종료하지 마라. 화면에 신규 기능이 보이지 않으면 서버 시작 시각과 파일 수정 시각을 비교해 오래된 프로세스 여부부터 확인하라.
>
> 각 기능 단위 완료 후 수정 파일, 변경 블록, 테스트 결과, 남은 위험을 보고하고 다음 단계로 넘어가라.
